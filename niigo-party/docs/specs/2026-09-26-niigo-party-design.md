## 0. 术语

| 词 | 含义 |
|---|---|
| **星币** | 局内资源。可被抢、可掉落。用于在商店买卡、在升级格换等级 |
| **等级** | 胜利条件。在**升级格**用星币换取，所需星币逐级递增 |
| **初始骰子** | 每个战斗判定掷一次的 1~6，独立于角色属性 |
| **奖励骰子** | 范围 = 角色属性 + 战斗牌加成，再在范围内随机 |
| **最终数值** | `初始骰子 + 角色基础属性 + 奖励骰子` |
| **战斗牌** | 只在战斗中用，扩大奖励骰范围。有消耗值 |
| **效果牌** | 对玩家或棋盘生效。每回合限用一张 |
| **反制牌** | 被效果牌指定时使用 |
| **倒地** | HP 归零。不淘汰，下一回合爬起来 |

## 1. 一局的骨架

### 1.1 回合状态机

一名玩家的回合依次经过这些阶段，**每个阶段都是服务器权威**：

```
turn_start
   ├─ 结算"回合开始"效果（中毒/回血等状态）
   ├─ 每 3 回合：发 1 张卡（回合开始奖励）
   ↓
roll            掷初始骰子（1~6），得到本回合移动点数
   ↓
move            逐格移动。每经过一格都要检查：
   ├─ 该格有对手？→ 弹战斗提示（可选择放弃）
   ├─ 该格有路障？→ 停止移动
   ↓
land            落地结算该格地块效果
   ├─ 部分地块会开出子阶段（见 §4）
   ↓
action          出牌窗口。每回合最多 1 张效果牌
   ↓
turn_end
   └─ 回合结束效果（如"以毒攻毒"的回血、状态倒计时）
   ↓
下一位玩家（按座位顺序）
```

**全局并行检视点**：反制牌是**响应式**的——任何人被效果牌指定时都能打出，不占自己回合。
所以 `action` 阶段之外也要有"等待响应"的挂起状态。⚠️ 响应窗口的超时策略需定。

### 1.2 子阶段

部分地块/卡牌会把状态机挂起，等一个额外的选择或掷骰：

| 子阶段 | 触发 | 等什么 |
|---|---|---|
| `battle` | 落到对手格 / 主动突击 | 双方依次选 防御 / 躲避 / 用战斗牌 |
| `gamble` | 猜猜乐地块 | 每人选单/双 |
| `lottery` | 彩票地块 | 每人选 1~12 一个数字 |
| `shop` | 商店地块 | 买卡 / 转账 |
| `destiny` | 个人命运地块 | 服务端随机，无输入 |
| `event` | 全员事件地块 | 服务端随机，全员受影响 |

> **一个必须的设计约束**：子阶段要能"等齐所有人"。
> 参考仓库既有教训（`showhand`）：**状态机的输入要显式收窄到"本次的有效参与者"**，
> 不要把全量 players 传进纯函数。观众 / 断线 / 已倒地的人会污染回合轮转。

## 2. 战斗系统

**这是最需要精确复刻的部分。三条规则互相咬合，抄错任何一条平衡就崩。**

### 2.1 数值构成

```
奖励骰范围 = 角色属性 + Σ(打出的战斗牌加成)
最终数值   = 初始骰子(1~6) + 角色属性 + 奖励骰
```

⚠️ `最终数值` 里**角色属性被算了几次**？Wiki 原文说"不要被攻击时显示的 3 个不同数值误导，
因为它们分别是你的初始骰子、角色的基础属性和奖励骰子之和"。按字面：属性只加一次。
而"奖励骰范围 = 基础攻击 + 卡牌加成"意味着属性**也参与了奖励骰的**范围定义**。
实现时先按"属性加一次，但决定奖励骰上限"来做，**跑通后用实际手感校准**。

### 2.2 判定流程

```
1. 攻方掷初始骰子 d_atk ∈ [1,6]
2. 受方选择：防御 或 躲避

   ── 若选【防御】──
   3a. 受方掷初始骰子 d_def ∈ [1,6]
   4a. 攻方最终值 = d_atk + atk + 奖励骰(攻)
       受方最终值 = d_def + def + 奖励骰(防)
   5a. 伤害 = 攻方最终值 − 受方最终值 − 其他修正
       ★ 伤害永远 ≥ 1（即使受方最终值更高）

   ── 若选【躲避】──
   3b. 受方掷 d_dodge ∈ [1,6]
   4b. 成功条件：
         d_atk < 6  →  需要 d_dodge > d_atk
         d_atk = 6  →  需要 d_dodge = 6
   5b. 成功 → 伤害 = 0
       失败 → 受方防御最终值视为 0
              伤害 = 攻方最终值（即 d_atk + atk + 奖励骰）

6. 伤害先被状态效果扣减（如"下次受伤 −2"），扣到 0 为止，不会变负
7. 结算 HP
```

### 2.3 三张对照表（实现时直接抄）

**躲避成功率要求：**

| 攻方初始骰子 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 躲避需要掷出 | 2 | 3 | 4 | 5 | 6 | 6 |

**注意**：成功率不是骰子大小决定的，是**比较**决定的。
`d_atk = 1` 时只要掷出 2 就躲掉（**成功率 5/6 ≈ 83%**）；
`d_atk = 6` 时只有掷出 6 才行（**成功率 1/6**）。
所以**攻方初始骰子越大，越难被躲**——这就是 Wiki 说"尽量掷出大于 3"的原因。

**由此推出的战术结论（要在 UI 里体现）：**

| 情况 | 该怎么选 |
|---|---|
| HP = 1 | **选躲避**。防御至少受 1 点必死；躲避有概率完全免伤 |
| 攻方初始骰子小（1~2） | 对方大概率会躲，考虑先不投入战斗牌 |
| 攻方初始骰子大（5~6） | 对方躲不掉，值得梭哈 |

### 2.4 战斗的触发与次数

| 触发方式 | 说明 |
|---|---|
| **落到对手同格** | 移动结束时若同格有对手 → 弹战斗提示，可选放弃 |
| **突击门** | 传送到对手位置后，可选是否战斗 |
| **通过移动经过对手** | ⚠️ Wiki 说"掷骰移动时可以连续与多个对手战斗"，但经过是否触发、还是只有落地触发，表述不明。**实现按"落地触发"**，跑通再调 |

### 2.5 战斗中的卡牌限制

- **每场战斗最多使用共 3 点消耗的战斗牌**（攻守双方各自 3 点？还是共享 3 点？）
  ⚠️ **这条例最不明确。** Wiki 原文："标准模式下，每场战斗最多可以使用共 3 费的战斗牌"。
  按"**攻守双方各自 3 点**"实现（更合理），跑通后校准。
- 攻方只能用攻击牌，受方只能用防御牌

## 3. 卡牌系统

### 3.1 三大类 × 作用对象

```
战斗牌
  ├─ 攻击牌（红底）  战斗中使用，提升我方奖励骰范围
  └─ 防御牌（浅蓝底）战斗中使用，提升我方（防守时）奖励骰范围

效果牌（每回合限用一张）
  ├─ 对自己   只能对自己使用
  ├─ 对目标   指定其他玩家（部分也可对自己）
  └─ 对地块   在棋盘上放置干扰

反制牌（响应式）
  └─ 被效果牌指定时使用
```

### 3.2 获取途径

- 每 3 回合的回合开始奖励
- 落到"卡牌奖励"地块（+2 张）
- 商店购买（3 星币/张）

### 3.3 最小可玩卡池（第一批只做这些）

**战斗牌（6 张 = 2 类型 × 3 档）**

| 卡 | 效果 | 消耗 |
|---|---|---|
| 攻击（中） | 攻击奖励骰 +1~3 | 1 |
| 攻击（大） | +1~6 | 2 |
| 攻击（特大） | +1~10 | 3 |
| 防御（中） | 防御奖励骰 +1~3 | 1 |
| 防御（大） | +1~6 | 2 |
| 防御（特大） | +1~10 | 3 |

**效果牌（先做 8 张，覆盖三种对象）**

| 卡 | 对象 | 效果 |
|---|---|---|
| 巧克力蛋糕 | 自己 | 回复 2 HP |
| 遥控骰子 | 自己 | 下次移动点数自选 1~6 |
| 皮筋弹弓 | 目标 | 10 格内造成 2 伤 |
| 板砖 | 目标 | 3 格内造成 5 伤 |
| 抢夺 | 目标 | 夺取目标 5 星币 |
| 钓鱼执法 | 地块 | 3 格内放置：踩上者付放置者 5 星币 |
| 爆破专家 | 地块 | 3 格内放置：踩上受 3 伤 |
| 路障 | 地块 | 3 格内放置：经过者停止移动 |

**反制牌（2 张）**

| 卡 | 效果 |
|---|---|
| 保护屏障 | 无效该效果牌 |
| 以牙还牙 | 把效果反弹给使用者 |

> 完整卡池有几十张（含 PVE 专属）。**第一批只做上面 16 张**——
> 先把"卡牌类型系统"做对，具体卡是数据，后面慢慢填。

## 4. 地块

### 4.1 最小可玩地块集（第一批 7 种）

| 地块 | 效果 | 为什么先做 |
|---|---|---|
| 保障点 / 起始点 | 停留回 2 HP；**星币达标自动获得 1 等级** | 胜利条件必需 |
| 卡牌奖励 | 获得 2 张卡 | 卡牌来源 |
| 天降横财 | 得随机星币（2/3/4/5/10） | 经济来源 |
| 天降横祸 | 受 2 伤；**若倒地，掉落一半星币在该格** | 风险的来源 |
| 商店 | 卖 3 张卡（3 星币/张）；踩到可免费得 1 张 | 卡牌来源 |
| 医院 | 回 2 HP + 随机住院；**免疫伤害、不可被效果牌选中、不可被挑战** | 战术安全位 |
| 疾行 | 可再次投点移动 | 节奏变化 |

**第二批再加**：个人命运、全员事件、占卜、炮台、猜猜乐、彩票、传送门、突击门。

### 4.2 棋盘形态

⚠️ **未定。** 这是设计缺口，且它决定走格动画需要几个方向。

| 选项 | 走格方向 | 交互密度 |
|---|---|---|
| 单条路径 / 环形轨道 | 1（+镜像） | 高，玩家必然互相踩 |
| 自由网格 | 4 | 低，玩家会互相避开 |

## 5. 胜利条件

```
星币  ──(到升级格)──▶  等级
```

- 升级所需星币**逐级递增**
- 第一个达到目标等级（或固定回合结束时分最高）者获胜

⚠️ 具体数值（目标等级、每级所需星币、回合上限）**未定**，需要数值设计。

**倾向**：固定回合上限（"到天亮"）+ 等级排名。理由：2 人局和 4 人局都能用，且时长可控。

## 6. 角色技能

**轴**：这是个互相干扰的派对游戏，角色差异体现在「**她怎么对待别人**」。

| 角色 | 姿态 | 主动技能方向 | 被动技能方向 |
|---|---|---|---|
| `mfy` 朝比奈まふゆ | **逃避** | 「优等生的假面」本回合免疫一次效果牌 | 被指定为效果牌目标时，有概率转移给随机玩家 |
| `ena` 東雲絵名 | **直接介入** | 「毒舌」指定一名玩家，随机弃其一张卡 | 查看某人的手牌数 / 偷看一张 |
| `kanade` 宵崎奏 | **单方面给予** | 「为你写歌」指定一名玩家获得增益（下次战斗属性 +N） | 在商店格额外获益（买卡打折 / 多拿一张） |
| `mizuki` 暁山瑞希 | **变形与隐藏** | 「改装」把一张手牌变成同类型随机另一张 | 自己的手牌数与状态对他人不可见 |

> ⚠️ **不要碰 Mizuki 的性别认同议题。** 用"爱打扮、做衣服、藏秘密"这类外围设定就够了。
> ⚠️ 以上是**方向不是数值**。四人技能平衡是后面最花时间的事，第一批先各做一个能跑的版本。

## 8. 联机契约

沿用仓库约定：消息统一 `{ type, data }` 信封，`core/protocol.js` 定义类型。

**服务器权威的范围**（一律服务端掷）：骰子、抽卡、地块随机、事件、彩票开奖。
**客户端只做**：渲染、本地演出动画、输入采集。

必须实现的端侧能力：
- 断线重连后状态恢复（用 `lobby-kit` 的 ws-client）
- **每次状态变更都广播自洽的完整状态帧** —— 仓库既有教训：只广播增量会出现
  "底池数字不动"这类状态失同步问题
