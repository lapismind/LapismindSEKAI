## 2. 回合流程（状态机）

一局按**轮**推进，每轮内四名玩家按座位顺序各行动一个**回合**。每回合依次经过：

```
turn_start（回合开始）
   ├─ 复活检查：自己处于 KO 且满足复活条件 → 播彩色光复活特效，回场（§6）
   ├─ 结算"回合开始"状态（中毒 / 回血 / 倒计时到期）
   ├─ 每 3 轮的回合开始：发 1 张卡
   ↓
roll    掷移动骰 **1d10（1~10，均值 5.5，服务端掷）**，得本回合移动点数
        （战斗判定骰也是 1d6，见 §4——移动骰与战斗骰是两套，互不影响）
   ↓
move    逐格移动（前端演出：走一格播一次步进，位移归代码）。
        每经过或到达一格检查：
        ├─ 叠加物（路障 / 陷阱）→ 停止移动并结算
        ├─ 交点 → 二选一走哪条环（§3）
        ├─ 传送门 → 立即跃迁到其中心对称格，继续走完剩余步数（§3.2）
        └─ 该格有对手 → 弹「可战斗」提示（见对手的防守插画），玩家自选：
             战斗 → 进入 battle 子阶段，打完继续走完剩余步数（星引擎同款）
             放过 → 继续走
   ↓
land    落地结算：
        ├─ 同格有对手 → 弹「可战斗」提示，可选战斗或放过
        ├─ 触发战斗 → 进入 battle 子阶段（§4）
        ├─ 其他地块效果 → 各自子阶段（shop / gamble / …）
        └─ 医院格等无事件 → 直接过
   ↓
action  出牌窗口：每回合最多 1 张效果牌（战斗牌只能在战斗中打）
   ↓
turn_end 回合结束状态结算、状态倒计时
   ↓
下一位玩家
```

**子阶段**（把主状态机挂起、等齐指定参与者的输入）：

| 子阶段 | 触发 | 等什么 |
|---|---|---|
| `battle` | 路过/落到对手格选择战斗、技能强制 | 双方依次：选战斗牌 → 防御/躲避 → 看结算（§4） |
| `shop` | 商店格 | 买卡 / 转账 |
| `branch` | 交点 | 选走哪条环 |
| `destiny` `event` `gamble` `lottery` | 二期地块 | 服务端随机或全员输入（二期再实现） |

**响应式输入**：反制牌在任何时候被效果牌指定都可打出，不占回合 → 状态机需要一个
`await_response` 挂起态。

**限时决策（已拍板）**：联机模式下所有需要玩家输入的决策期都限时——
**进攻方 / 先手方 9 秒，防守方 / 响应方 10 秒**（攻防决策期合计给防守方留余地）。
超时默认"不出牌"；防守方超时默认选**防御**（稳妥方向）。**热座模式不受此限**。

**实现约束（沿用仓库既有教训）**：子阶段的输入收窄到"本次有效参与者"，不把全量
players 传进纯函数——KO 中的玩家、断线者、观众一律不得进入等待名单。

**服务器权威范围**：骰子、抽卡、地块随机、战斗判定、KO/复活判定全部服务端算；
客户端只做渲染、演出、输入采集。**每次状态变更广播自洽的完整状态帧**（不广播增量）。

## 3. 棋盘结构（双矩形 45° 互穿，按用户手绘稿）

**形态（用户手绘稿为权威）**：两条矩形环**相对旋转 45° 互穿**，周线相交出 **4 个交点**——
中央被两环围出一个正方形，每个环各有两段瓣伸出中央区外，共四个外伸瓣（十字花/八角星形）。

**草图（v3，2026-09-26，格数与分布待用户确认）**：[`board-sketch-twin-loop.png`](board-sketch-twin-loop.png)

### 3.1 拓扑（68 格 = 外环 36 + 内环 36 − 4 个交点共享格）

- 结构沿用手绘稿：双矩形 45° 互穿、4 交点围出中央正方形（5×5 格距）、四个外伸瓣
- **外伸瓣大幅加长**（瓣长 4 格、瓣侧 5 格：每瓣 12 自有格），总格数 36 → 68
- **两环等长（各 36 格）**，地块分布 **180° 中心对称**（t(格) = t(其中心对称格)）；
  起始点 ×2、商店/医院/升级各 ×2 成对
- **性格分工 = 对角同性格**：
  - **A 的对角瓣对（↗↙）= 稳健**：横财（稳健版）×12、卡牌 ×6、商店 ×2、疾行 ×4、
    起始 ×2、传送门 ×2、横祸 ×4
  - **B 的对角瓣对（↖↘）= 高收益高风险**：高收益横财 ×8、横祸 ×8、医院 ×2（兜底）、
    升级 ×2、试炼格 ×2、卡牌 ×6、横财 ×4（中央边）
  - 险瓣期望收益略高（~8.4 vs ~5.9 币/轮，见 §5.4）是对横祸密度与 KO 风险的补偿，
    实战中被 KO 损失（一半星币 + 缺席一轮）拉平——平衡校准点
- 交点 = 博弈点：切环决策 + 两环玩家在交点**十字交叉相遇**
- **移动 = 单骰 1d10（均值 5.5）**：一圈 68 格 ≈ **12.4 轮**——放大与加速必须一起做，
  否则节奏崩坏（传送门/疾行是主要加速器，节奏表见 §5.4）

## 4. 战斗系统

### 4.1 演出分层（已冻结的呈现方式 + 插画体系）

```
路过/落到对手格 → 弹对手的防守插画（健康版）提示「可战斗？」→ 玩家选战斗或放过
   ↓ 选战斗
【插画层】进攻方的进攻插画 + 防守方的防守插画拼接成过场（方案 A「VS 斜分屏」，§4.6）
   ↓
【战位层】镜头拉近到棋盘局部或切独立场景：
   攻守双方 chibi 贴片面对面站位（共用同一套棋盘 chibi，按战斗尺寸出）
   ↓
结算演出全在战位层进行：选牌 UI → 掷骰数字 → 伤害数字 / 受击表现（MVP：抖动+红闪）
   ↓
败者 HP≤0 → KO 流程（§6）；攻方继续走完剩余移动步数（星引擎同款）
```

**进战插画体系（已定稿）**：每素材键 **1 张进攻插画 + 2 张防守插画**
（防守插画按当前 HP 切换：HP ≥ 50% 用健康版，< 50% 用濒危版）。**5 键 × 3 = 15 张**
（mfy 两形态各出一套）。素材待产，MVP 用纯 UI 过场顶替。

**不是全屏插画播完就完**——插画只是进战仪式感，判定与结算在战位层可交互进行。

| 特殊牌 | 「全力攻击」最终攻击力 +50%（原文表述有歧义，标注存疑）、效果不可叠加；免伤/易伤改最终伤害增减；护盾 = 额外生命；固定伤害无视防御 | 同上 |
| 战斗后 | 战斗结束后攻方**继续前进直到移动点数耗尽** | [NGA Demo 感想（2024-02）](https://bbs.nga.cn) |
| 牌型定义 | 战斗牌"可增加战斗骰子的总范围"：攻击牌（红底）加攻击者、防御牌加防守方；战斗数值 = 基础属性（增益生效前）+ 两个随机数（初始骰子 + 奖励骰子） | [astralparty.wiki.gg Mechanics](https://astralparty.wiki.gg/wiki/Mechanics)（**页现已清空**，仅存搜索引擎快照摘要） |
| 档位 | "3 星攻击牌（1~10）" → 牌的星级档位与数值范围挂钩，与 TapTap"特大 1~10"一致 | Steam 社区讨论（快照摘要） |

**查证残留（不阻塞实现，数值校准时处理）**：

- "中/大"档（1 费/2 费）的具体范围查证不到，**已由用户定稿为 1~4 / 1~7**（3 费 = 1~10 有查证印证）
- **出牌时机**（先出牌定加成再掷骰，还是先掷骰再补牌；游侠网表述暗示"双方出完牌后攻方掷骰"）
- 两种表述并存且数值上不等价：TapTap 版"**牌直接加到点数上**（牌自带随机数）" vs
  wiki 快照版"**牌扩大奖励骰的范围**"。**已拍板按 TapTap 版实现**（见下方实现基线）。

**实现基线（按查证结果落地）**：

```
最终攻击力 = 角色面板 ATK + 攻击牌值 + 骰子数
最终防御力 = 角色面板 DEF + 防御牌值 + 骰子数
伤害 = max(1, 最终攻击力 − 最终防御力 − 状态修正)   ★ 伤害 ≥ 1
```

- **费用体系（已定稿）**：每张战斗牌有消耗，三档 = **1 / 2 / 3 费**；**每场每人最多打 3 费**
- **roll 范围（已定稿）**：1 费 = **1~4**、2 费 = **1~7**、3 费 = **1~10**（出牌时系统随机取值，
  按 TapTap 版"牌直接加点数"实现；3 费档有查证印证，1/2 费档由用户拍板定稿）
- 属性加成次数问题被 TapTap 公式化解：面板只加一次，牌也只加一次

### 4.3 闪避对照表（实现与 UI 提示直接引用）

## 6. KO 与复活（已冻结，细则已拍板）

```
HP ≤ 0（战斗 / 板砖 / 地块 / 陷阱皆可）
   ↓ 被击飞（位移归代码：飞多远代码定，素材只给静态姿态）
【KO 状态】
   ├─ 原格贴片调暗变黑（MVP：贴片整体压黑 + 压低饱和；KO 坐地图素材到位后替换为坐地图）
   ├─ 跳过自己的回合；**免疫所有事件**（已拍板）：不可被挑战、不可被效果牌指定、
   │   不吃地块/陷阱/事件效果——一切事件对 KO 者无效
   ├─ 被打倒时，加害者**直接抢走其一半星币**（不落格，§6.2）
   ↓ 满足复活条件（§6.1）
【复活（已拍板）】
   ├─ **彩色光盖住一闪**：全屏/局部彩色光遮罩闪一下盖过过渡（代码特效，素材零成本方向）
   ├─ 贴片恢复明亮，**HP 回满**，原地复活
   └─ 正常进入本回合
```

### 6.1 "一回合后复活"的实现定义

- KO 时记 `koAtTurn`（当前全局回合序号）。
- 复活条件：再次轮到该玩家、且**从 KO 起全员各行动过一次**（即缺席恰好一轮）→ 该次 `turn_start` 复活。
- 边界：在自己的回合内被打倒（如行动阶段被反伤）→ 同样缺席下一轮；在别人的回合被打倒（板砖）→ 若本轮还没轮到自己则本轮跳过，否则缺席一轮。以 `缺席一次自己的行动机会` 为准绳实现。

### 6.2 KO 抢币规则（v2.4 修正，已拍板）

- **普通战斗胜利（未 KO）：无任何星币效果**——只是把对方 HP 打下去。战斗不是收入来源。
- **造成 KO 才抢币**：加害者**直接抢走败者一半星币**（败者保留一半，**不落格、别人捡不到**），
  败者缺席一回合后原地复活回满（§6.1）。
- "加害者"的归属：战斗 KO = 胜者；板砖 / 爆破专家等卡牌陷阱 KO = 打出者；
  **无归属的 KO（天降横祸等地块）无抢币**——死于地图比死于玩家便宜，鼓励玩家互斗。

- 不可被抢：KO 者与住院者（免疫所有事件，§6/§3.2）。

## 8. MVP 切分与里程碑

### M0 —— 单机热座最小闭环（只用现有静态图，无网络）

**可玩标准**：4 个本地座位（热座轮替）能完整打完一局。

- 选人：从 5 个素材键选 4 个（mfy 双形态算两个候选，局内可切换、纯外观）
- **双矩形 45° 互穿棋盘**（68 格草案，4 交点，中心对称）× 地块集（含传送门/试炼格），代码绘制背景；交点二选一切环
- 掷骰 → 逐格平移演出（静态贴片 + 浮动）→ 路过/落地可选战斗 → 落地结算
- 16 张卡全量可用（1/2/3 费体系、手牌上限 10），反制牌 MVP 可先简化为"无响应窗口、直接生效"；**热座不限时**
- 战斗：插画拼接过场（UI 占位）→ 战位层（贴片对峙）→ 完整 §4 判定 → 攻方继续走完步数
- KO / 复活全流程（压黑占位 + 彩色光复活特效）
- 升级胜利 + 回合上限兜底结算

结构上按三层放：`src/core/`（协议与抽象接口）、`src/game/`（规则逻辑，纯函数可单测）、
`src/network/`（通信）。**M0 把 `src/game/` 写厚、网络层留接口**，M1 只换通信不换规则。

### M1 —— 联机化

- lobby-kit 接入（房间码 / 邀请链接 / 断线重连），`NiigoRoom` DO 升级为服务器权威游戏宿主
- 消息 `{type, data}` 信封，`core/protocol.js` 定类型；**完整状态帧广播**
- 决策限时上线（9s / 10s，§2）
- **人机补位不在本阶段**（已拍板后置）；2~4 名真人即可开局

### M2 —— 素材替换与数值校准

- KO 坐地图、棋盘背景、进战插画（15 张，方案 A）、立绘选人、卡面、地块图标按 §7 到货逐项替换占位
- 跑平衡：重点校准经济设计稿（§5.4）与战斗牌 1/2 费档 roll 范围（§5.2）

### M3 —— 小游戏层（二期差异化）

每 6 轮一场全员小游戏（借鉴《揍击派对》，第一个候选：抽乌龟），赌注星币/卡牌；
经济位置已预留（名次奖 +12/+8/+4/0，25 轮内 4 场，§5.4）；
"高兴/失落"情绪贴片在此成为高频落点（素材到位后）。

### M4 —— 动画量产接入

本地 H3 就绪后按素材仓库动画清单（12 动作 × 5 键）分批替换静态贴片：
掷骰 / 攻击 / 受击 / 躲避优先（战斗表现提升最大），走跑次之。

### M5 —— 人机 AI（已拍板后置：规则稳定后再做）

图版层规则与数值稳定后，补位 AI 按简单策略起步（随机走 + 见人就打 + 有钱买卡），
再逐步按角色性格分化。
