## 为什么是梭哈

海龟汤上线之后，验证了一整套联机架构能跑。第二个游戏的目标很明确：**把能复用的全部沉淀成包，只写游戏逻辑本身**。

选了五张/七张梭哈（Five/Stud Showhand）：规则清晰、轮次明确、天然多人对抗，正好检验大厅层的通用性（其实是我从初中开始就爱玩）。

## 大厅层抽成了 lobby-kit

第一个游戏做完就发现：昵称、头像、房间码、WebSocket 连接、邀请链接——这些每个联机游戏都要写一遍的东西，本质上是同一个"大厅层"。

我好歹是个前端出身嘛，遇到这种可以抽象复用的东西敏感的不行。

这次直接把它抽成了 `@lapismind/lobby-kit`：

- **WebSocket 客户端**：连接、断线自动重连、消息分发
- **房间码**：6 位大写字母数字（排除易混淆的 0/O/1/I）
- **玩家身份**：playerId 生成 + HMAC 签名 token
- **个人资料组件**：昵称输入 + 26 张头像九宫格

showhand 只写"发牌、下注、摊牌、结算"，大厅部分零重复代码。这个思路被验证是对的——后续第三个游戏接入成本会进一步降低。

## 技术架构

跟海龟汤同一套底座：

```
浏览器 ──WebSocket──► Worker 入口
                        ├─ /ws  → ShowhandRoom DO（每桌一实例）
                        └─ 静态资源 → 前端 dist/
```

核心是一个 Durable Objects 状态机，管理完整的牌局生命周期：

- **发牌节奏**：五张模式 1 暗 + 4 明；七张模式 2 暗 + 4 明 + 1 暗
- **下注轮转**：每轮按顺序行动，超时 Alarm 自动弃牌
- **摊牌结算**：7 选 5 最优牌型，并列赢家平分底池
- **观众席**：上帝视角实时推送，防作弊验证

## 几个有意思的坑

**1. All-in 不是立即摊牌。** 初版实现全下后直接开牌，直接就赢了（我测试的时候是真没绷住），没做判断，这太过分了——别人还可以选择不跟或弃牌。修正后的流程：全下后其他人仍可行动，跟注后才把所有人的牌补满到该发的张数再摊牌。

**2. 平分底池的余数。** 两家平分 101 底池怎么办？规则定为从庄位下家开始依次多拿 1，直到分完。

**3. 自己的暗牌要有标识。** 暗牌和明牌视觉上分不清的话，玩家不知道哪两张是自己独有的。加了呼吸光圈动画只标自己的暗牌。

**4. playerId 不能信任 URL 参数。** 初版直接从 URL 读 playerId 就认定身份，任何人改个参数就能冒充别人。加了 HMAC 签名 token：服务端 /api/identity 签发，WS 升级时双层校验。

## UI 迭代过程

初版牌桌是个 CSS 半透明椭圆，丑得有特点。后来经历了四轮迭代：

1. SVG 手绘毛毡质感 + 木纹边框
2. 找了现成的八角桌 PNG，flood-fill 擦掉白底换上
3. 桌子放大到撑满视口，玩家卡片环形分布
4. 其实还是很丑，但是这个以后再解决吧，精力花在别处
5. 浅粉紫主题统一（#F2EBF7），白卡片浮在浅紫底上

筹码也从 emoji 🪙 换成了 SVG 绘制的真筹码样式。
