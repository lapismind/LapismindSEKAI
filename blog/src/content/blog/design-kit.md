## 起因：文档和实现分叉了，而且不报错

梭哈上线那篇文章里，我写过一句"浅粉紫主题统一（#F2EBF7）"。

前几天改牌桌，顺手算了一下博客页面底色的真实值：`oklch(0.972 0.014 249)`，也就是 **#EFF7FF** —— 极浅的冷调白。因为博客的 `--hue-bg = 283 - 34`，从紫往冷的方向走了 34 度，落进了蓝区。

文档写着香芋紫，实现是淡蓝白，**差了 34 度色相，挂了很久没人发现。**

为什么没发现？因为没有任何地方会因此报错。构建不失败、测试不失败、页面不崩——它只是"两个地方的颜色不一样"，而这种错误没有任何机制会拦住它。

更糟的是副本数量。同一个 `#8888CC` 当时有**四份**定义：

- 博客一套 oklch 令牌（由 `--hue-accent` 推导）
- showhand / abracadawhat / turtle-soup **各抄一份一字不差的 `--color-brand-*` hex 块**
- lobby-kit 的组件里还硬编码了几个（`AuthBadge` 的主按钮是 `#6b6bd0`，跟品牌色根本不是同一个值）

改一次要改四处，而且必然漏掉一处。

## 收成一个包

于是建了 `@lapismind/design-kit`，跟之前抽 lobby-kit、chat-kit 一个思路。它现在管四件事：

| 文件 | 内容 |
|---|---|
| `tokens.css` | 30 个设计令牌。品牌色由 `--hue-accent: 283` 一个数字经 OKLCH 推导，亮/暗两套表面色 |
| `theme.css` | Tailwind 色阶（供 `bg-brand-*` 这类工具类）+ 语义颜色层 |
| `base.css` | 底色、字体、面板配方、入场基元、动效降级 |
| `fonts/` | 霞鹜文楷 97 个子集 + 同步脚本 |

消费方式就是两行 `@import`。四个项目（博客 + 三个游戏）现在都从它取色。换主色只需要改 `--hue-accent` 一个数字。

下面这些是迁移过程中真正踩到的东西，比"抽个包"本身有指导意义得多。

## 1. 同一个值有两种写法，就必须有自检

Tailwind 4 的 `@theme` **只接受静态值**。品牌色阶要生成 `bg-brand-600` 这类工具类，就必须写 hex；而 `tokens.css` 要支持"改一个色相换全套"，就必须用 oklch 推导。

于是品牌色不得不**在两处以两种写法各存一份**——这正是我想消灭的那种重复，但它在这里是技术必需的。

既然消灭不了，就给它加一道自检：`tests/tokens.test.mjs` 把 `theme.css` 里的 `#8888CC` 反算成 oklch，校验它和 `tokens.css` 的 `--hue-accent` 色相一致（实测 `oklch(0.654 0.101 283.3)`，注释里写的也是这个值）。改主色时两处一起改，跑一次测试就知道有没有对齐。

**消灭不了重复的时候，就把它变成会被检测的重复。**

## 2. 按角色命名，而不是按色值命名

比色值更值得抽的是**角色**。同一个地位的东西在不同主题下是不同色值，但角色不变。

所以有了语义颜色层：组件里写 `bg-surface`、`text-ink`、`border-line`、`bg-chrome`，不写 `bg-[var(--card-bg)]`，更不写死 hex。前者换主题自动生效，后两者一个啰嗦、一个换主题就失效。

这里有个 Tailwind 的坑值得记：**品牌色阶用普通 `@theme`，语义层必须用 `@theme inline`。**

- 普通 `@theme` 要求静态值，写 `var()` 会在构建期被固化成当前主题的颜色，切换主题就失效
- `@theme inline` 把 `var()` 原样保留进产物、不预先求值，主题切换对工具类同样生效

判断标准一句话：**这个值要不要跟着主题走。** 要 → `inline` 并指向 `tokens.css`；不要（比如品牌 11 档是人工排的、不随主题变）→ 普通 `@theme` 写死。

## 3. 动效也会失控

配色统一了，节奏还是乱的：七八种时长、五六种缓动，摆在一起看起来就是"没设计过"。

所以也收进包：**一条缓动曲线 + 四档时长 + 一个错峰间隔**，各项目不要再自己写数字。另外给了一条阈值——位移 ≤ 6px、缩放 ≤ 3%，只动 `opacity` / 小位移 / 颜色 / 阴影；不做回弹、旋转、超过 6px 的位移。

阈值这条比令牌更重要：令牌解决"用哪个数"，阈值解决"该不该动"。

## 4. 入场动画有个静默失败

`.reveal`（滚进视口淡入上升）的初始态是 `opacity: 0`。这意味着**观察脚本一旦没跑起来——JS 报错、被拦截、换页时漏绑——内容就永久不可见**。页面不报错、不白屏，只是缺了一块。

修法是在 `<head>` 的内联脚本里先给 `<html>` 打上 `has-js`，CSS 只在 `has-js` 存在时才隐藏：没脚本 = 直接是最终态，绝不空白。

同类还有一个：`prefers-reduced-motion` 下不能"把时长压到 0"——那等于让人必须滚到才有内容。要给**最终态**，不是给零时长。这两条现在都写死在 `base.css` 里。

## 5. 大二进制不进 git

字体子集 5.2MB、97 个文件。进 git 会让每次 clone 都拖上它，四个项目各存一份就是 20MB。

做法沿用 chat-kit 对表情包的处理：**只留一份真源**（`fonts/`），消费方在 `predev` / `prebuild` 里同步到自己的 `public/fonts/`，产物目录 gitignore。

顺带说清为什么必须拷贝、不能直接引包路径：Vite/Astro 只把项目的 `public/` 按原路径静态托管，而 `@font-face` 的 `url()` 是运行时请求，必须落在真正可访问的路径上。

**这里踩了一个真实的坑**：海龟汤的 `deploy` 脚本当时是自己写的 `vite build && wrangler deploy`，绕过了 `npm run build`，于是 `prebuild` 的字体同步根本没跑——代码是对的，上线就是没字体。所以现在所有项目部署一律走 `npm run deploy`，不自己拆构建命令。

## 6. 深色项目最容易脱节

海龟汤是常驻深色的。之前它把 `--bg-deep: #1c1c33` 这些深色表面色写在自己 CSS 里——**看起来"它有自己的风格"，实际上是它和设计语言脱节了**：亮色项目改了底色它不知道，它的 202 处 `bg-slate-*` 也各自硬编码在各个组件里。

这次让它把深色身份改成 `data-theme="dark"` 声明，表面色全部走语义令牌。迁移量 202 处。

**结论：深色项目不是"例外"，只是"另一种主题"。** 它该做的是选另一套令牌，而不是自己声明一套。

## 7. 迁移要量化，不要靠眼睛

迁移这种"只换写法、不该改观感"的改动，最怕悄悄改坏了。用到两个手段：

**对比度审计**（解析 `tokens.css` 的真值来算，不硬编码色值）：20 项里 19 项达 AA。唯一不达标的是"小字号 `brand-600` 配白字"（4.16:1）——核了迁移 diff 确认是既有问题、不是本轮引入。

**"核 diff"这个动作比结论重要。** 记录里写着"这是既有问题"，但记录可以引用、结论要自己验。逐行看过迁移 diff，`bg-brand-600` 一行都没动，才敢认定它是既有的。

还有一条是关于**对比方法**：一开始想用"线上截图 vs 本地截图"判断本轮有没有改观感，后来意识到这个对比的前提是"线上等于改动前的那次提交"。当时线上落后好几轮，这个对比横跨多个提交，差点把更早一版的改动算到本轮头上。真正能判定的只有两条：**查迁移 diff（这个值改没改）、算绝对值（达不达标）。**

## 边界：不是所有颜色都该进令牌

也有明确**不该**进包的东西：牌桌的台面渐变、筹码的红色、卡牌的花色。它们是游戏物件的固有色，`var()` 在那些上下文里没有意义，而且本来就该有强对比。

判断标准不是"这个值复不复杂"，而是**"它是不是表达了一个语义角色"**。是角色就进包，是物件的固有外观就留在项目里。

## 最大的教训：文档里的色值也是副本

这次最该记住的不是技术，是开头那件事——

**`docs/LOBBY-KIT-COLORS.md` 里那张色值表，本身就是第五份副本。** 它和实现分叉了很久，没有任何机制会发现。

所以那份文档现在不再列色值，只讲"为什么"和"新项目怎么接"，色值指向 design-kit。同理，博客的 `AGENTS.md` 与 `docs/site-features.md` 里凡是写着"令牌在 `global.css`"的地方，也一并改成了指向真源。

**文档应该指向真源，而不是复制真源。**

这条可以推广成一句比"这段代码复不复杂"更准的判断标准：

> 同一份值抄在多处，必然会分叉，而且不会报错。
> 该不该收口，不看它复不复杂，看**它是不是本该系统里只有一份**。

## 结果

四站（博客 + 三个游戏）现在共用一套令牌与字体：品牌色 11 档、表面色亮暗两套、圆角与阴影阶梯、两套字体栈、一套动效节奏。线上旧调色板残留 0 处，四站 `body` 字体一致。

顺带把梭哈那篇文章配的绿毡桌子换成了现在的实拍截图。至于那篇里写的 `#F2EBF7`——就当作是当时的我以为吧。
