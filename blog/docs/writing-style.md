# 本站文章的行文风格

> 起草或修改 `src/content/blog/` 里的文章**之前**读这份。
> 依据是四篇样本，其中后三篇是用户改定的终稿——**以终稿为准，不要以 AI 初稿为准**：
>
> | 样本 | 状态 | 用途 |
> |---|---|---|
> | `rune-staff.md` | 用户大幅改过 | 主样本：改动最大，能看出他会删什么、加什么 |
> | `tts-studio.md` | 用户改过 | 技术型文章的结构与对账写法 |
> | `blog-editor.md` | 用户改过 | 元话题（为什么这么干）怎么讲 |
> | `mmd-footer-banner.md` | 用户写的 | 短篇、纯经历、无技术 |
>
> 2026-09-25：这份规则是从「AI 初稿 → 用户终稿」的逐段对照里提炼的。对照证据见 §8。

## 1. 一句话

**他在写自己的经历，不是在介绍一个项目。** 信息量让位给画面感；能一眼看懂的先讲，需要前置知识的要么砍要么放到最后。

## 2. 开头（起因）

- 第一句直接说事，不铺垫、不设问、不解释背景。
  - ✅「做的是《怪物猎人 荒野》的外观替换：给盾斧换成一把日式魔女法杖。」
  - ✅「页脚之前太单薄了，就想着加点二次元的东西进去。」
  - ❌「在开始之前，让我们先了解一下这个项目的背景。」
- **灵感/起因要落到自己的经历上**，不要只说"参考了某某"：
  - ✅「一是我玩 MHRS 的时候是打的惠惠 mod，有配套的魔法杖替换掉盾斧；结果这个理科魔女 Mod 质量挺高的，但是荒野就没人用什么法杖造型做盾斧了，我就想吧既然 AI 建模现在这么厉害，那就自己动手呗。」
- 起因常见三段式：**我遇到什么 → 找不到现成的 → 那自己做**。

## 3. 署名节「代码方面」

紧跟起因，单独一节，**极简**，一行一个阶段：

```
## 代码方面
v1.0  **DeepSeek V4.1 Flash**

v1.1  **Astra High**
```

- 模型名要写全（`Astra High`，不是 `Astra`）。
- 用户的角色一并写清：定方向、拍板、进游戏验收、说"这不是我要的"。
- 不许把用户没写的代码算在他头上。

## 4. 正文：坑怎么讲

**一个坑 = 一段画面 + 一句根因 + 现在怎么防。** 按故事讲，不按文档讲。

- 先说**看到的症状**（越具体越好笑越好）：
  - ✅「第一次进游戏手上拿了个生紫绣的青铜器（后续出问题还搞了一个出土黄铜文物版本）。belike:」
  - ✅「一按变形切斧形态，杖头直接爆成碎片飞出去。」
- 再说**当时的误判**，这是最有价值的部分：
  - ✅「我以为是面数不够，其实不是。」
  - ✅「以为是逻辑写反了，实际是它每秒闪一次。」
- 然后是**根因**，只给能一眼看懂的那一层：
  - ✅「75% 的面来自 1.2 毫米的无差别倒角」
  - ❌「Boolean union 把底模的 Grip 权重传给新几何，头部 2839 个顶点硬带 `Grip=1.0`」——需要前置知识，用户直接删了整节
- **宁可少讲三个坑，也别每个坑都讲透。** 讲完几个就收：
  - ✅「实际上一路上遇到的 bug 远远都不止这些，后续也不再赘述了」
- 数字要给**具体值**，但只留读者能感受的那个：`10793 帧、242 秒`、`98 厘米`、`1251 个顶点`、`均亮 126.6 到 189.1`。查证过程的中间量不用报。
- 小标题用**问题式口语短句**，不用名词化标题：
  - ✅「开始堆形状」「低模？」「法阵」「防御才出现的法阵，管理器做不了」「刚开始翻了好多车」
  - ❌「设计与实现」「技术架构」「方案选型与权衡」

## 5. 用词与语气

- 短句、口语连接词：就 / 呗 / 吧 / 得了 / 寻思 / 好家伙 / 我去 / 毕竟 / 反正 / 结果 / 于是 / 不过 / 其实 / 挺 / 一下。
- **情绪要写出来**，不要中立叙述：
  - ✅「好家伙，我只能说 **Astra 大人**是真的牛。」
  - ✅「这个是真的上了大当，……浪费了好多时间验证游戏完整性。」
  - ✅「要是我有用不完的 Astra 就好了。」
- AI/工具用口语昵称，不用全称：`牢鲸`、`大鲸鱼`、`Astra 大人`、`狩枝盒子`。
- 自嘲、直说自己不懂或舍不得：✅「我不知道 Astra 写起文章能不能避免这一点，我舍不得用哈哈 XD。」
- **不追求零错别字。** 终稿里「法张」「生紫绣」「狩枝」都在。逐字打磨反而破坏口吻。
- 括号插话随时补前提或吐槽：✅「（一般也不会想用中配吧？）」「（后续出问题还搞了一个出土黄铜文物版本）」。

## 6. 结构模板

```
## 起因            ← 我遇到什么 / 找不到现成的 / 自己做
## 代码方面         ← 谁做的，一行一个阶段
## <第一个坑>       ← 症状 → 误判 → 根因（能一眼看懂的）
## <继续堆东西>
## <核心设计>       ← 讲清楚"这一版为什么好看"
## <实机/效果坑>
## v1.0 / v1.1 ...
## 一些限制         ← 清单式，版权/体积/前置条件
## 最后             ← 2~3 句，极短
```

- `一些限制` 用无序列表，一条一句，写事实（版权归属、体积、前置、不分发什么）。
- 篇幅弹性很大：技术型可以到 200 行（`tts-studio`），纯经历 45 行也行（`mmd-footer-banner`）。
- 表格只用在**对账/对比**（前后数值、角色差异），不用来排版普通信息。

## 7. 结尾「最后」

- **极短，2~3 句。不升华、不总结全文、不给鸡汤。**
- 可以是一句总结 + 一句情绪 + 一句开放尾巴：
  - ✅「这一路最花时间的其实不是建模，是"以为是 A，结果是 B"。……症状和根因每次都不在同一个地方，Deepseek 每次都只能猜，我也跟着一遍一遍的重试。／要是我有用不完的 Astra 就好了。／下一步想试法阵的透明和流动感。成不成得看游戏着色器认不认。」
  - ✅「也许以后会加新的角色？看到时候有什么需求吧。」
  - ✅「不然我只会向 AI 许愿。」
- ❌ 任何形式的「相信未来会更好」「这不仅是……更是……」「希望能给大家带来启发」。

## 8. 禁用清单（AI 味）

以下特征**一出现就删**。右边是本次实际被用户改掉的例子。

| 禁用 | 为什么 |
|---|---|
| 「不仅……而且」「既是……也是」 | 排比腔 |
| 「值得一提的是」「不得不说」「综上」「总而言之」 | 论文腔 |
| 「这体现了」「这标志着」「背后是……的思考」 | 强行拔高 |
| 首先/其次/最后 三段式并列 | 模板腔 |
| 每段结尾都小结一句 | 逐字推出来的"顺理成章" |
| 「让我们」「不难看出」「可以看到」 | 讲解腔 |
| 把工程日志里的发现**逐条倒完** | 读者要"这段经历什么样"，不是"我们查出了什么" |
| 中立叙述技术过程，不带情绪 | 变成说明书 |

**逐段对照（本次 `rune-staff.md` 的真实改动）：**

| AI 初稿 | 用户终稿 | 规则 |
|---|---|---|
| 「还有原版那把矛的头（Group_3）一直没删，它伸到 y=−1.99 的位置。v1 有 496 个面挂在游戏根本不认识的 `OrnMetal` 上，这些都是后面才清的。」 | 整段删除，换成「实际上一路上遇到的 bug 远远都不止这些，后续也不再赘述了」 | 日志发现不必倒完 |
| 「（配饰的造型参考了「理科魔女」那个角色，后面说。）」 | 「一是我玩 MHRS 的时候是打的惠惠 mod……」 | 灵感落到亲身经历 |
| 「## 斧形态下杖头散成碎片」（整节讲权重） | 整节删除 | 需要前置知识的坑砍掉 |
| 「## 核对数字会骗人」（整节讲 IoU / 假验证） | 整节删除 | 同上 |
| 「后来它还自己承认了另一处：> 之前把一些材质问题归到造型上……」（大段引述） | 「好家伙，我只能说 **Astra 大人**是真的牛。」 | 引述换情绪 |
| 「## 你说这还是低模」 | 「## 低模？」 | 标题要短、要口语 |

## 9. 标题

- 口语、有钩子，常见三种：「为了……我……」「……之后」「首谈……」

  - ✅「为了页脚五个馒头人，装了一晚上 MMD」
  - ✅「同一个颜色抄了四遍之后：把设计语言收成 design-kit」
  - ✅「首谈法杖盾斧的开发历程」
  - ✅「给洛茜的 mod 配上语音，顺带完善语音合成工作台」

- 不用副标题式的冒号长句，不用「原理与实践」。

## 10. 图片与排版

- 图片**插在相关段落之后**，单独成行，前后留空行。
- 编辑器拖进去会自动命名并插入：`![hash](../../assets/posts/hash.png)`，正文里**不解释图**（要说话就一句吐槽，见 `belike:` 的用法）。
- 封面走 `heroImage` + `heroImageAlt`，`heroImageAlt` 描述画面内容（无障碍用），不是标题重复。
- 视频/代码块：代码块只用来放**协议通道和管线**（`tts-studio` 里的进程图），不用来贴实现片段。

## 11. 交稿前自检

- [ ] 第一句是不是直接说事，没有铺垫
- [ ] 有没有一处「我以为是 A，其实是 B」
- [ ] 每个坑是不是都讲太透了（砍掉至少一个）
- [ ] 有没有出现 §8 表里的任何词
- [ ] 「最后」是不是 ≤3 句、且没有升华
- [ ] 情绪有没有写出来（自嘲 / 惊讶 / 舍不得）
- [ ] 署名节是否照实、且模型名写全
- [ ] 有没有为了通顺把口语改成书面语
