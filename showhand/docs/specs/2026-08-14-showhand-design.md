## 1. 概述

多人联机梭哈网页游戏，支持五张梭哈与七张梭哈两种玩法，固定局数积分赛制。
技术栈复用海龟汤已验证路径：Vue3 + Vite + Tailwind + Cloudflare Workers + Durable Objects + WebSocket。

## 2. 玩法规则

### 2.1 牌局模式

| 模式 | 发牌 | 说明 |
|------|------|------|
| 五张梭哈 | 1 暗 + 4 明（共 5 张） | 底牌 1 张暗牌，4 张明牌逐张亮出 |
| 七张梭哈 | 3 暗 + 4 明（共 7 张） | 前 3 张暗（含 2 底牌），4 张明牌逐张亮出 |

- 每轮发牌前/后下注，暗牌保密，明牌全桌可见
- 发牌顺序固定顺时针

### 2.2 下注

- 动作：**跟注 / 加注 / 弃牌 / 全下**
- **多次加注**：本轮被加注后可再加注（德州式）
- 每轮 **30 秒倒计时**，超时自动弃牌
- 牌型大小：同花顺 > 四条 > 葫芦 > 同花 > 顺子 > 三条 > 两对 > 一对 > 高牌

### 2.3 赛制

- **人数**：牌桌 4-8 人，观众席不设限
- **模式**：开局房主选五张/七张，一房到底
- **局数**：房主设定固定局数（默认 10 局）
- **筹码**：房主设定初始筹码（默认 1000），筹码即积分
- **输光**：筹码不足时全下，输光后出局，转为观众
- **结束**：固定局数跑完 → 按总筹码排名，冠军揭晓

## 3. 角色与视角

| 角色 | 状态 | 权限 |
|------|------|------|
| 玩家 | 有筹码、在牌桌上 | 自己暗牌可见，可下注 |
| 输光者 | 筹码归零 | 自动转观众，上帝视角 |
| 超员观众 | 超过牌桌人数上限加入 | 进观众席旁观 |
| 观众 | 任意 | **对局中即可看所有玩家暗牌**（上帝视角），可切换 |

- 防剧透交给玩家自觉（与线下围观一致）
- 观众无法下注或影响牌局

## 4. 技术架构

### 4.1 后端（Cloudflare Workers + Durable Objects）

```
浏览器 ──WebSocket──► Worker 入口(index.js)
                        ├─ /ws     → ShowhandRoom DO（每房一个实例）
                        ├─ /api    → 房间列表 / 加入
                        └─ 静态资源 → 前端 dist/
```

- `ShowhandRoom` DO：单实例管理房间全部状态（发牌、下注、结算、观众席）
- **服务端权威发牌**：洗牌/发牌在 DO 内，客户端拿不到未发的牌，防作弊
- SQLite 持久化：断线重连恢复房间状态
- 状态机：`等待玩家 → 发牌中 → 下注中(逐轮) → 摊牌 → 结算 → 下一局`

### 4.2 前端（Vue3 + Vite + Tailwind）

- **玩家视角**：自己暗牌可见 + 全桌明牌 + 下注按钮
- **观众视角**（上帝）：任意玩家牌全可见，可切换视角
- Pinia 管理客户端状态，WebSocket 客户端复用海龟汤 network 层设计
- 下注 UI：跟 / 加 / 弃 / 全下按钮，30 秒倒计时条

### 4.3 协议（消息流）

- 服务端 → 客户端：`room_state`（全桌状态）、`your_hand`（你的暗牌）、`turn_to`（轮到谁）、`bet_result`、`showdown`（摊牌）、`game_over`
- 客户端 → 服务端：`join`、`bet`（跟/加/弃/全下）、`sit_out`、`spectate`

### 4.4 防作弊要点

- 只有 DO 知道完整牌堆，客户端只收到自己的暗牌
- 观众视角展示的信息由服务端标记，客户端不可越权
- 服务端校验所有 bet 动作的合法性（金额、顺序、次数）

## 5. 关键风险与对策

| 风险 | 对策 |
|------|------|
| 下注状态机复杂度（多次加注轮转、全下、摊牌判定） | 状态机分层设计，先实现单轮跟/加/弃，再扩展多次加注 |
| 防作弊依赖服务端持牌 | 客户端零信任，所有校验在 DO |
| 断线中断牌局 | SQLite 持久化 + 重连恢复 + 30 秒超时自动处理 |
| 全下后筹码不足的下注结算 | 分池（side pot）逻辑，按投入顺序结算 |
