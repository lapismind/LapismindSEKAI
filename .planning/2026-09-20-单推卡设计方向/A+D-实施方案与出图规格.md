## 0. 用户为什么选 A+D

原话：**"A D结合很有说法啊，本来 mfy 确实也是个双面角色，只有暗色模式能看到'谢谢你 找到了我'
这样设计会使得这句话没那么廉价"**。

这补上了设计稿缺的最后一块：**签名句不该是常驻标语**。它是"被放进来"的报酬——只有愿意待在夜里的人能看到。
（同时它也是这份方案里最需要小心处理可访问性的一处，做法见 §3.4。）

## 1. 概念（一句话）

**这张卡是一只水槽：她的履历浮在水面上，她的心沉在水下；而切换主题不是换配色，是镜头入水。**

融合点：A 的"亮＝白天的水族馆 / 暗＝整张卡在水下"与 D 的"亮＝她给世界看的那层 / 暗＝她自己"**本来就是同一件事**，
所以两个方向不是拼接而是同一叙事的两个面。

## 2. 已实现（纯 CSS，不依赖任何新素材）

### 2.1 结构：线上 / 线下两层

`DOM 顺序 = 视觉顺序 = 读屏顺序`，资料仍是文本，搜索"162cm""田辺留依"照样命中。

| 层 | 内容 | 为什么在这 |
|---|---|---|
| 水面之上 `.oshi-above` | 姓名 + 日文名、单元徽章、**六项可量化资料**（生日/年龄/身高/CV/趣味/擅长，3 列 × 2 行） | 履历＝她愿意给人看的 |
| **水面线** | `.oshi-below::before`（2px 高光带）+ `::after`（30px 柔光带） | **画在"线下第一件事"的容器顶边上**，所以它永远压在分层交界，不会因资料换行漂到字中间 |
| 水面之下 `.oshi-below` | **喜欢的食物（妈妈亲手做的菜）+ 不擅长（表达情绪）**、主题句 + 水下倒影、签名句、涟漪 | 官方资料里最私密的两条 + 两句说不出口的 |

**把八项拆成 6+2 的依据是数据本身**：`喜欢的食物：妈妈亲手做的菜` 和 `不擅长：表达情绪` 是她官方设定里
最私密的两条，正好从"八项等权"的网格里被救出来——`auto-fit` 网格给了「身高 162cm」和「表达情绪」同样的字号字重，
那正是原设计没有观点的证据。

- `.oshi-above { max-width: 30em }`：**右侧的留白就是她的位置**，这条不能删（删了她到货时会没地方站，事实格子也会排成 4 列）。
- `.oshi-depth-key .v` 提一档字号 + 一颗缓慢上浮的气泡（`oshi-rise`，6s）。
- `.oshi-theme::after` 用 `attr(data-text)` 做 `scaleY(-1)` + `blur(2px)` + `mask` 渐隐的**倒影**：同一句话出现两次，
  第二次是画面的一部分——这是"把文字交给画面"最直接的手法。

### 2.2 亮 / 暗是两个叙事，不是两套配色

- **亮（白天的水族馆）**：卡面 `--oshi-surface`（极浅紫白）→ `--oshi-shallow`（极浅冷青白），
  水面线是一条 2px 白高光 + 30px 柔光带。
- **暗（你就在水里）**：水面线移出卡外（`opacity: 0`），整张卡是深水渐变，
  光由 `.oshi-card::after` 的**一道斜光柱**承担（`clip-path` 多边形 + 低透明渐变，**全卡只此一处发光**，
  符合上一轮"发光密度是最重的 AI 味来源"的纪律）。
- 水色是 `.oshi-card` 上的局部变量，改几个值就能整体调水面。

### 2.3 顺手删掉的两件东西

- `.oshi-moon`（420px 光斑）：它是**占位符的形状**——锚在卡外靠 `overflow:hidden` 裁切，暗色下是全卡最显眼的东西、
  亮色下几乎看不见，两个主题连构图都不是同一张。她到货后由她自己当光源。
- `.oshi-snow`（6 个无限下落圆点）：**这张卡是 `src/` 里唯一没有 `prefers-reduced-motion` 兜底的页面**
  （`IntroOverlay` / `BaseHead` / `Footer` / `index` / `global.css` 六处都有）。删掉它等于修掉那个缺口；
  新加的涟漪与气泡动画都写了兜底。

### 2.5 两个踩过的坑（都是我自己踩的）

1. **`@keyframes` 里的 `opacity` 会压过普通声明**。涟漪的关键帧原本动了 `opacity`，于是暗色那条
   `.oshi-ripple { opacity: 0 }` 被直接盖掉，涟漪在水下也在闪。改成**关键帧只动 `transform`**，
   `opacity` 留在普通声明里由主题切换。
2. **`.oshi-fact .k { flex: 0 0 4.6em }` 的 em 是按标签自己的字号算的**（`0.72rem` → 4.6em 只有 53px），
   装不下「喜欢的食物」（5 个字）。改成 `flex: 0 0 auto`，值仍 `text-align: right`，两栏照样对齐。

### 3.4 「签名句只在暗色可见」怎么做得不违反对比度

亮色下**不显示字形**，只留一道水下涟漪；`<span class="sr-only">` 里始终有一份真文本，
所以读屏**永远读得到、且只读一次**：

```html
<p class="oshi-tagline-slot">
  <span class="oshi-ripple" aria-hidden="true"></span>
  <span class="oshi-tagline" aria-hidden="true">「谢谢你，找到了我。」</span>
  <span class="sr-only">「谢谢你，找到了我。」</span>
</p>
```

- 视觉层 `aria-hidden`，暗色下 `opacity: 1`（`--dur-slow` 淡入）；亮色 `opacity: 0` 且**不是文字**（只有涟漪），
  所以不存在"低对比度的可见文字"这个问题。
- 槽位固定 `min-height`，切主题**不跳版**。
- 代价要如实说：**亮色用户看不到这句话**。站点右上角的主题开关就是唯一的入口——这是设计意图（它是报酬），
  但要接受"多数访客可能永远看不到"。若想让它可被发现，可以给亮色加一句提示（例如一个 `25:00` 的等宽小字），
  **这句文案属于用户**，本方案没有替他编。

### 3.5 接入方式（含一个 CSS 约束，别踩）

她在 `.oshi-figure`（绝对定位、出血越过卡右缘）。"头肩穿过水面"要做成**同一张图渲染两层**：
水上一份原图、水下一份加 `filter: saturate(.65) blur(1.5px)`，两片在**同一位置**、各自被裁到自己的深度层。

**注意一个陷阱**：设计稿写的是"靠 `overflow: hidden` 分层裁切"，但**用 `.oshi-above` / `.oshi-below`
包一层 `overflow:hidden` 是裁不住的**——按规范，绝对定位元素若其**包含块在该裁切元素之外**（这里包含块是
`.oshi-card`），则**不受该裁切**。所以不要那样写。

可行的做法（确定性、可验收）：把水面线做成**一个长度变量 `--oshi-wl-h`（从卡片顶边算起）**，
`top: var(--oshi-wl-h)` 画线、`.oshi-above { min-height: calc(var(--oshi-wl-h) - 1.7rem) }` 让分层交界落在同一条线上、
两份图各用 `clip-path: inset(0 0 calc(100% - var(--oshi-wl-h)) 0)` 与 `inset(var(--oshi-wl-h) 0 0 0)`。
**验收时必须专门看一眼水面线有没有压在文字上**（资料换行会让上层变高，这时要同步改这个变量）。
若最终嫌麻烦，降级做法是只用一张图、把水面线画在她**前面**（z-index 高于她），效果差一点但绝不会错。

## 5. 待定 / 需要用户定的

- **手机端她要不要出场**（本轮新出现的决定）。实测 390 下内容列约 290px，而资料是"标签左、值右"的单列、
  数值本来就贴右缘 —— 设计稿提的"右侧出血窄条（`min(190px, 52vw)`）"**放不下**，会压到数值。
  现在预览页的做法是**窄屏不画她**：只靠水的分层、倒影与签名句的开关成立（插画＝渐进增强）。
  要让她在手机上也出场，需要**另一种排法**（例如她占顶部一条、文字从下面开始），那是另一个决定，
  不是把桌面版缩小。
- 亮色下要不要给一个"下面还有东西"的提示文案（本方案只留了一道涟漪，没有编文案）。
- 「裏」要不要连**发丝漂浮**一起做（那是一次中等幅度的编辑）；只改光照与表情是更保险的最小版。
- 水色最终值（`--oshi-surface` / `--oshi-shallow` / `--oshi-deep`）在她到货后可能要跟着她的肤色微调，
  这是设计稿标为"最难一步"的地方，只改那三个值即可。

## 7. 水槽里的时间（已实现，纯 CSS）

设计稿 A.2 那句"水面在动、波光在动，倒影跟着晃"本轮补上了：

| 元素 | 做法 | 纪律 |
|---|---|---|
| 波光 `caustic-a/b/c` | 两层不等距斜向条带（96° 与 36°，差 60° 才有干涉）反向异速 + 一层错开径向柔光斑，模糊 15–24px，46s/71s/88s 错拍 | 亮色 opacity 0.42/0.3/0.5；**暗色压到 0.13/0.09/0.1**——暗色只有一道光柱，全卡仅此一处发光 |
| 气泡 `bubble` ×4 | 从水底 `translate3d` 上升 300px，接近水面淡出，13–21s 异速、负延迟错开 | 只 4 颗、小（4–7px）、只在水平线以下 |
| 倒影晃动 | `.oshi-theme::after` 加 `oshi-wobble`（`scaleY(-1)` + 横向 7px 往复，9s） | **这一条比波光更能让水"活"**，成本却最低 |
| **水面浪** `.oshi-surface` | 两层内联 SVG 正弦波（16 段 / 12 段整数周期，元素 200% 宽，横移量 = 100/(2×段数)% → **无缝循环**）反向异速 21s/13s；浪尖高光是 SVG 描边（`non-scaling-stroke`）；整个水面 9s 上下"呼吸" ±2px | 亮色 0.85/0.7；**暗色 0.3/0.26**（留一道很淡的浪＝"水面在你上方"，与光柱同源）。**验证：两层各平移一个周期后逐像素比，最大差 2–5、超阈值像素 0** |
| 玻璃边 | `inset 0 0 0 1px` 高光，加在原来的 `--shadow-sm` 后面 | 让卡读起来是"一缸水"而不是一块渐变 |
| 层叠 | `.oshi-water { z-index: -1 }` + 给 `.oshi-card` 显式 `z-index: 0` | **卡面必须自己建立层叠上下文**，否则负 z-index 的水层会落到卡面之后被盖住 |

全部动画只动 `transform` / `opacity`，`prefers-reduced-motion: reduce` 下五处全停（含原有的涟漪与气泡）。
实测水层确实在画：**卡片级像素差 亮 7.5% / 暗 20.2%**（水下带内 10% / 27%）。
水浪的三个坑（幅度小了只是"波浪边"、浪体填充会在盒子底边切出直线、均值线要对齐水线）记在 `blog/docs/lessons-learned.md` 第 34 条。

## 7.5 亮色的水色：一次返工（用户："白天的水族箱这个配色味道不对"）

第一版亮色是 `--oshi-surface: 淡紫（hue-accent 283）→ --oshi-shallow: 灰蓝（243）` 的跨卡渐变。问题有三层：

1. **上半是淡紫**——那是真冬的紫，不是"水面上方的空气"。掺进水里就成了"一块紫色面板"。
2. **下半是灰蓝**，不是水色；再叠上白色波光，就成了雾和灰（"味道不对"的来源）。
3. **边界是渐变的中点**，所以读起来是"一块褪色的紫灰面板"，不是"一缸水"。

改法：

| 部位 | 现在的值 | 道理 |
|---|---|---|
| 水面之上（空气/玻璃） | `oklch(0.985 0.006 252)` 近白冷调 | **不要再掺真冬的紫**——掺了就是紫色面板 |
| 水（浅） | `oklch(0.935 0.05 202)` | 色相落在青区（200–212）。**要读成水得靠彩度，不是靠变暗**；变暗只会得到脏灰 |
| 水（深） | `oklch(0.862 0.08 212)` | 两档都保持足够亮，下面小字才够对比度 |
| 水从哪开始 | `.oshi-below` 自己铺（出血到卡的三边） | 水的边界＝分层边界，不再是跨卡渐变的中点 |
| 版权行 | 移回 `.oshi-below` 之内 | 它原来是兄弟节点，坐在近白的空气色上——**水到它那儿就断了**；现在它在水底 |

**顺带修的两处（都是配色返工才暴露的）**：
- **对比度**：青水比原来的灰蓝亮，`--muted`（0.55）压上去只有 **3.98:1（k 标签）**，没过 AA。
  亮色下水下换一档更深的次级色 `oklch(0.46 0.03 240)`；改完线上实测 k 标签 **5.82**、主题句 **12.08**，
  暗色 5.71 / 15.01，全部 ≥4.5 ✓。
- **卡片里的版权行已删**（用户："那个版权字直接不要了，网站底部就已经有版权说明了，那个是历史遗留产物"）。
  删掉后卡片高度 654 → **559**，底部那条带正好交给造景。
- **预览页的主题改写漏了 `:not()`**：我写的是 `:root:not([data-theme='dark'])`，而改写规则只处理 `:root[data-theme='dark']`，
  于是这条"亮色专用"规则漏进了预览页的暗色面板（k 标签量出 2.55:1 的**假故障**）。
  生成器的 `theme_scope()` 现在两种写法都改写。**教训：预览页的保真问题会伪装成 CSS bug，先在线上复核再改代码。**

## 7.6 造景（SVG，无生物）与权限最重的一个层叠 bug

用户要求："能用 SVG 之类绘制一些水族箱里的素材吗？不要生物，水族箱留空，但是要放点东西。"
于是画了 **7 件惰性造景**（全部内联 SVG、跟着主题换色、零体积）：

| 件 | 用色（亮 / 暗） | 说明 |
|---|---|---|
| 底砂 | 砂米 `oklch(0.9 0.05 88)` / `0.6 0.045 86` | 两层缓坡，横跨整宽，顶缘是波浪 |
| 石头 ×2 | 青灰 `0.67 0.012 250` / `0.5` | 左区两块，各带一档亮面 |
| 沉木 | 棕 `0.44 0.055 58` / `0.36` | 主枝斜卧 + 长短差开的枝杈（粗笔画当枝） |
| 陶罐 | 赭红 `0.64 0.1 45` / `0.5` | 水族箱里的经典摆件 |
| 过滤管 | 塑料灰 `0.74 0.012 200` / `0.56` | 贴右壁，下段带滤网槽 |
| 温度计 | 玻璃 + 水银红 `0.62 0.17 25` / `0.68` | 挂右壁靠水面（**左壁是文字所在，竖件必然穿字**） |

风格守站内语言：平涂、硬边、一档描边（`--oshi-line`）、无渐变无高光。**用真实材质色是有意的**——
缸里本来就是暖色的东西泡在冷色的水里，这些暖色不打架，反而让整只缸"有东西"了。

### 层叠 bug（这才是"看不见"的真原因）

第一版造景**报"看不见"，我误判成"画得淡"，还给它编了"含蓄"的理由**。真因是：

`.oshi-below` 只有 `position: relative`、`z-index: auto`，**不构成层叠上下文**。于是它内部
`z-index: -1` 的水层（波光 + 造景）被提升到卡片那一层去找层叠上下文，结果**画在了 `.oshi-below`
自己的水色渐变底下** —— 那道 alpha 0.96 的渐变把整层盖住，只漏出约 4%。修法是给 `.oshi-below`
加 `z-index: 0` 让它自己成为层叠上下文（与 `.oshi-card` 同理，那张卡当初也踩过同一条）。

**教训（写进 lessons-learned 第 36 条）**：我当时的"验收"是量"水层有没有贡献像素"（7.5%，非零），
而不是"人看不看得见"。**判据设成"有贡献"就等于没判据**——用户那句"只有 AI 能通过像素判断出来"
才是对的验收。

顺带：这一次修完，亮色的**波光也变得可见**了（此前同样被水色盖住，只有约 4% 漏出）——
所以这不是只修造景，是把整个水层还回来了。

## 8. 可选：把"水族箱"做成图（用户提的方向）

用户原话："如果我用个水族箱作为背景，再加上水浮动的特效，就很好了。"
**特效那半已经用 CSS 做了**（上一节）。背景这半有两条路，我推荐第一条：

### 8.1 推荐：一张透明"水槽内景"装饰层（1 张）

在水平线以下的最底部叠一层水草／沉木／沙石剪影，只做"槽里有东西"的暗示。
**关键优势：它不承载信息，所以完全不碰文字对比度**（整卡背景画做不到这一点）。

- 尺寸：**比例约 5:1 的横幅**（例：1500×300），接进来时贴卡片下缘、宽度 100%。
- 透明底：纯单一绿 `#00FF00` 平涂底 + 硬边；去背脚本一次性、可复跑。
- 体积：**≤60KB WebP**。
- 提示词：

```
flat matte anime-cel shading, hard-edged shapes, few tone steps, clean line art,
silhouette-like aquatic plants, no glow bloom, no sparkles, no light rays,
no floating particles, no lettering, no watermark.

内容：水族箱底部的内景装饰，一条横向的窄带 —— 几丛细长水草、一块深色沉木、几块圆润的卵石，
最下面一条沙底。**只有剪影感、低对比**，不要细节堆叠，不要鱼。
构图：5:1 横幅，元素集中在带子的下半部，上半部留空（接进来后上面就是她的身体与文字）。
背景：纯单一绿色 #00FF00 平涂底，无渐变、无投影。
```

- 接入：叠在 `.oshi-water` 里、`bottom: 0`，`opacity` 亮色约 0.5 / 暗色约 0.35 —— 目标是"隐约看出是个水槽"，
  不是一幅画。

### 8.2 备选：整卡背景画（2 张，亮暗各一）

一张画好的水族箱内景铺满卡面。**代价要说清楚**：① 文字对比度必须靠画里预留暗区（得写进提示词，且 6 项资料所在的上半区要低对比）；
② 2 张图、体积翻倍；③ **画里的发光/粒子会和 CSS 的水打架**（两次"水在动"），得在提示词里否掉光效。
只有确实想要"整卡是一张画"的观感时才走这条。

## 9. 验收清单（水这轮补充）

7. 水层**确实画出来了**：卡片级像素差（带水 / 不带水两张截图相减）亮暗都不为 0；只改 CSS 不看结论。
8. `prefers-reduced-motion: reduce` 下 `.caustic-a/b/c`、`.bubble`、`.oshi-bubble`、`.oshi-ripple`、
   `.oshi-theme::after` 六处 `animation-name` 全为 `none`。
9. 暗色的水面光要**明显弱于**亮色（压到 0.09–0.13），确保"暗色只有一道光柱"。
10. 预览页与线上**逐元素高度相等**（不然预览在说谎）。
