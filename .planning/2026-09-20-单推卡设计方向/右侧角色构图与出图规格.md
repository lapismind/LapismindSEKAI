**画布 2:3 竖幅（1024×1536）；她的下巴咬住水面线（y = 282）。**
亮色 = 头浮在水面上（下巴以上是空气，肩以下在水里）；暗色 = **同一张图整体下移 0.6 × 水线（169px）**，头顶落到水面线下方 28px。

## 1. 构图决策

### 1.1 她在画布上的锚点（唯一的硬规格）

| 锚点 | 值 | 性质 |
|---|---|---|
| **下巴（下巴尖 ↔ 脖颈交界那一线）** | **画布高度 50%** | **硬锚点，唯一的** |
| 头顶 | 画布高度 ~27% | 容差 20–32% 都成立 |
| 画布下缘 | 切在**胯**（内容 = 头顶到胯，约 3.2 头身） | 容差 ±1 头身 |
| 身体中轴 | 画布宽度 **50%**（±3%） | 容差 48–58% |
| 左侧轮廓 | **不许被画布左缘裁切**（留 ≥5% 余量） | 硬规则（= 不许压文字，见 1.5） |
| 右肩 / 右臂 / 马尾尾端 | **被画布右缘裁切**（出画） | 硬规则（出血） |

### 1.2 为什么锚在"下巴"

用户原话是"**白天头浮在水面上**"。水族馆里"头浮在水面"的读法只有一种：**水面横切在脖颈上**——
头在水面之上（干的、清晰的），肩与胸在水面之下（入水的）。所以那条线要落在**下巴与脖颈的交界**，
不是眼睛（那是"沉到只剩眼睛"，另一种叙事），也不是胸口（那是"站在水里"）。

### 1.3 亮色：头浮在水面上，怎么落地

- 显示高度 = **2 × 水线** = 2 × 282 = **564px**；下巴在画布 50% ⇒ **她的下巴永远落在水线上**，不需要第二个变量。
- 实测：水面浪的均值线正好在 **y = 282.1**（`.oshi-surface` 盒 y 270.9、盒高 22、均值在盒内 11px）。
  所以"下巴落在 282"和"浪横穿她的脖子"是同一件事。
- 肩线落在 **y ≈ 327**（下巴往下 0.35 头 ≈ 45px）→ 肩以下全部在水里，交给入水滤镜（§2.2）。
- 头顶在 **y ≈ 154**，距卡顶 154px 是"水面之上的空气"——**这段空白由她的高马尾负责填**（§1.6）。

### 1.4 暗色：沉到水面之下，怎么落地

**同一张图（暗色编辑版），CSS 平移 `translateY(calc(var(--oshi-wl-h) * 0.6))` = 169px：**

| | 亮色 | 暗色 |
|---|---|---|
| 头顶 y | 154 | **310** |
| 下巴 y | **282（= 水线）** | 451 |
| 水线 y | 282（浪 + 高光带都在） | 282（浪压到 0.3/0.26，**仍在**：读作"水面在你上方"） |
| 读法 | 头在水面之上 | **头顶在水线下方 28px，整个人在水下** |

- 为什么是 **0.6**：0.5（141px）时头顶只低于水线 13px，像"刚好贴着水面"而不是沉下去；
  0.7（197px）时肩线掉到卡底之外，只剩一个头，损失身体。0.6 是"沉下去、但还看得见她"的点。
- 暗色下**不需要两片裁切**（她整个在水线以下，水线不穿过她），只有一张、一层、一个滤镜（§2.7）。
- 平移做成过渡（`--dur-slow`）：切主题时她**滑下去**，不是跳过去——这一步本身就是"下沉"的动作。

### 1.5 容差与一条自证安全的规则

模型不一定听话，所以规格要有安全带：**头顶 20–32%、中轴 48–58%、画布下缘从腰到膝上都读得通。**
**下巴 50% 不能错**（错 20px 就变成"水线切到她的嘴/肩"，叙事立刻走样）。

一条免费的保险：**"她不被画布左缘裁切"** 就等于 **"她压不到文字"**。
理由（实测）：画布左缘落在卡内 **x ≈ 499**，而卡内**最深的一处文字墨迹只到 x = 477.2**
（单元徽章那一行，y 80–95；六项资料最深是「英语会话」466.4 / 「162cm」453；主题句墨迹只到 389.8）。
两者差 22px，且她比徽章低 60px 以上。所以只要她的轮廓不出左画，就一定在文字右侧。
**这条规则不需要额外测量，也不需要模型理解"左边有字"。**

### 1.6 朝向、视线、手、马尾（构图的四条硬规则）

1. **3/4 侧身朝画面左前**，视线朝左下方，**不看镜头**；半睁的"营业表情"、没有笑容、没有悲伤。
2. **左臂贴身**：不许举高、不许向左伸出（那是唯一会撞到文字的姿势）。
3. **右臂自然下垂** → 右臂与右肩被右缘裁掉 = 出血。
4. **高马尾向右上方扬起，尾端出右缘**：它同时干两件事——出血，以及填掉右上那块 260×154 的空白。
   **只有右缘可以裁她，上缘不可以**（头发被上缘切一刀会读成"裁图事故"）。

### 1.7 她与水面的前后关系（谁压谁）

| 元素 | 在她前面还是后面 | 为什么 |
|---|---|---|
| 水色渐变、波光、造景、气泡 | **后面** | 她是主体，不是水的一部分 |
| 水面浪（`.oshi-surface`） | **后面** | `.wave-front` 的填充是近白的 `--oshi-surface`（alpha .94），压在她前面会在胸口刷一条白带 |
| 水面高光带（`.oshi-below::before/::after`） | 后面 | 同上 |
| **她身上单独一道水面线**（`.oshi-figline`，§2.6） | **前面** | 浪被她挡住约 130px，需要这一道把水面线补连续 |
| 文字 | **前面** | 她永远在 x > 499，文字最深 477——不重叠，但顺序上文字在上更保险 |

## 2. 出图比例与接入尺寸

### 2.1 画布 **2:3 竖幅（1024×1536）**——推导

| 量 | 值 | 来源 |
|---|---|---|
| 水线 y | **282** | 实测（1440 视口） |
| 画布显示高 H | **564** = 2 × 282 | 下巴咬水线 + 下巴在画布 50% |
| 可见宽 | **260** = 卡的右 34%（x 500 → 760） | 实测空位（文字最深墨迹 477，留 22px 余量） |
| 出血 | **116** = 画布的 31% | 见下 |
| 画布显示宽 W | 376 = 260 + 116 | |
| **比例** | 376 : 564 = **2 : 3** | **出图直接出 2:3，不要出方图再裁** |

**为什么必须是 2:3（三个候选的取舍）：**

**可见宽恒为 260**（她的位置锚在卡右缘），所以画布越宽 ⇒ 主体越靠右。按"模型会把主体放在画面正中"算：

| 比例 | 画布宽 | 出血 | 主体居中后（卡宽 760） | 判定 |
|---|---|---|---|---|
| 5:8（0.625） | 353 | 93（26%） | 中轴 x 676；右肩 772、**只超出卡缘 12px** | ✗ 出血太弱，读成"框里放了一个人" |
| **2:3（0.667）** | **376** | **116（31%）** | **中轴 x 688；右肩 784、超出 24px，马尾超出 ~48px；头离右缘 24px** | **✓ 出血成立、头完整** |
| 3:4（0.75） | 423 | 163（39%） | 中轴 x 711；右肩超出 47px，但**头的右缘离卡缘只剩 0.5px** | ✗ 头有被切的风险（发型一宽就切脸） |

**结论：2:3 是唯一同时满足"出血读得出来"与"头一定不被切"的区间**；而且 1024×1536 是模型的原生竖幅档位。
（出图比例一次出对，是上一轮"出 1024 方图再裁切"的教训。）
左侧那 260px 里没有文字墨迹（最深 477.2，画布左缘落在 499），所以**三个比例的左侧都是安全的**——
真正卡住上限的是右缘：画布越宽，她越被推到卡缘外，头先被切。

### 2.2 接入几何（可直接抄）

**导出时把右侧永远不会被看见的 116px 出血裁掉**（卡的 `overflow:hidden` 永远切在卡右缘，那 116px 在任何视口都不可见）
→ 交付图 = **520×1128**（= 显示 260×564 的 2 倍），体积省约 40%。

> **一个必须写死的配套条件**：裁掉出血的版本**必须 `right: 0` 严格对齐卡右缘**。
> 她"出画"这件事已经被烘进素材（源图里她被画布右缘切断，导出时把那 116px 连同她出画的那一截一起裁掉）。
> 若以后想让出血更多/更少，**不能改 `right` 的值**（那会在卡内露出一条垂直硬切线），
> 而要改用未裁的 2:3 源图（768×1152）+ `right: -Npx`。这是这个省体积方案唯一的代价。

```css
.oshi-card {
  /* 水面线：一个长度变量，三件事共用 —— 浪的均值线 / 分层交界 / 她的下巴 */
  --oshi-wl-h: 282px;
  /* 她的显示宽 = 高 × 260/564（2:3 画布裁掉不可见的右侧出血后的比例）。
     用变量算，水线变了她也不会被拉伸。 */
  --oshi-fig-w: calc(var(--oshi-wl-h) * 0.922);
}

/* 作画层：锚在卡的右缘，自己不吃排版。z-index:1 是必须的（§2.3） */
.oshi-figure {
  position: absolute;
  right: 0;
  top: 0;
  width: 0;
  height: 0;
  z-index: 1;
  pointer-events: none;
}
/* 亮/暗两组：靠 opacity 交叉淡入，各自独立（不写在同一元素上，见教训 21） */
.oshi-fig {
  position: absolute;
  right: 0;
  top: 0;
  width: 0;
  height: 0;
}
/* 两片共用同一块画布：高 = 2 × 水线（下巴就在它的 50%），右缘对齐卡右缘 */
.oshi-fig-layer {
  position: absolute;
  right: 0;
  top: 0;
  width: var(--oshi-fig-w);
  height: calc(var(--oshi-wl-h) * 2);
}
.oshi-fig-layer > img {
  position: absolute;
  inset: 0;
  width: 100%;
  height: 100%;
}
/* 水面之上：原图 */
.oshi-fig-layer--above {
  clip-path: inset(0 0 calc(100% - var(--oshi-wl-h)) 0);
}
/* 水面之下：同图同位置 + 入水滤镜。
   裁切在外层、平移在内层 —— 实测：写在同一元素上，裁切会跟着 transform 一起走（§2.4） */
.oshi-fig-layer--under {

  filter: saturate(0.72) blur(1.5px);

}
/* 暗色：整张卡在水下，她整体下沉。只留一层、不裁、不接缝 */
.oshi-fig--night .oshi-fig-layer {
  clip-path: none;
  filter: saturate(0.72) blur(1.2px);
  opacity: 1;
}
.oshi-fig--night .oshi-fig-layer > img {
  transition: transform var(--dur-slow) var(--ease-soft);
}
:root[data-theme='dark'] .oshi-fig--night .oshi-fig-layer > img {
  transform: translateY(calc(var(--oshi-wl-h) * 0.6));
}
/* 交叉淡入 */
.oshi-fig--day,
.oshi-fig--night {
  transition: opacity var(--dur-slow) var(--ease-soft);
}
:root[data-theme='dark'] .oshi-fig--day { opacity: 0; }
:root[data-theme='dark'] .oshi-fig--night { opacity: 1; }

/* 水面在她身上那一道：只有亮色需要（暗色她整身在水下，不穿线） */
.oshi-figline {
  position: absolute;
  right: 0;
  top: var(--oshi-wl-h);
  width: var(--oshi-fig-w);
  height: 2px;

}

/* 窄屏不画她（§2.8） */

}
@media (prefers-reduced-motion: reduce) {
```

两个 `<img>` 同 URL → **只下载一次**；整卡新增 **2 个文件**（亮/暗各一）。

### 2.3 层叠：她必须 `z-index: 1`（有实测证据，别省）

`.oshi-below` 是 `z-index: 0` 的层叠上下文，`.oshi-figure` 现状是 `z-index: auto` →
两者同属"定位后代"这一组、按**文档顺序**绘制，`.oshi-figure` 在前 ⇒ **被 `.oshi-below` 的水色渐变（alpha .96）盖住**。

实测（把一块 260×559 的纯红放进 `.oshi-figure`）：

| `.oshi-figure` 的 z-index | 水线以上 y=124 | 水线以下 y=374 |
|---|---|---|
| `auto`（现状） | `(255, 6, 6)` 红 | **`(184, 228, 235)` —— 纯水色，她 0% 可见** |
| `1` | `(255, 1, 1)` 红 | `(255, 1, 1)` 红 |

**这就是 A+D 方案 §7.6 那个"造景看不见"的 bug 的同一个形状**：水层 alpha .96，下面的一切只漏出 4%，肉眼等于没有。
**她必须 `z-index: 1`**；代价是她也在文字层之上——但她在 x > 499、文字最深 477，所以安全（同 §1.5）。

### 2.4 裁切与平移必须分层（有实测证据）

实测：一个 60×100 的盒子写 `clip-path: inset(0 0 50% 0)` + `transform: translateY(120px)`，
可见像素只出现在 **y +139**（即被裁的"上半"跟着 transform 一起下去了）。

| 写法 | 结果 |
|---|---|
| 裁切 + 平移写在同一元素 | ✗ 平移时"水面线以下"这一片会跟着她一起动，裁切线失效 |
| **裁切在外层 `.oshi-fig-layer`、平移在内层 `img`** | ✓ 裁切线钉在卡的水面上，她在下面动 |

|---|---|---|---|---|---|
| 1440 | 760 × **558.6** | 569.8 | **477.2**（徽章行 y 80–95） | **282.1** | y 270.9，高 22 |

1. **水线在 721–1440 全区间都是 282.1**（只有 701–767 之间会低 2px，因为她不出场，无所谓）

> 水下的文字若将来多出一行（+28px）就会破这条 → 届时**只改一个数**：把源图的"下巴到画布下缘"加长，

### 2.6 水面在她身上那一道（`.oshi-figline`）

浪被她的身体挡住约 130px，所以需要一道 2px、白色 0.8 的高光把水面线在她身上补连续。
**它只覆盖她那一列（宽 = `--oshi-fig-w`）**，不横穿整卡。
若实装后发现它和后面的浪尖高光读成"两条线"，**直接删掉这个元素**（两分钟的事，不影响别的）。

### 2.7 亮暗两版怎么平移 / 换图

| | 亮色 | 暗色 |
|---|---|---|
| 用哪张图 | 亮色版（文生图产物） | 暗色版（亮色版的编辑产物） |
| 分片 | 两片（水线上清晰 / 水线下入水滤镜） | 一片（整身在水下，不裁） |
| 位置 | 下巴在水线（画布 top = 0） | `translateY(0.6 × 水线)` = 169px |
| 交叉淡入 | `.oshi-fig--day` opacity 1 → 0 | `.oshi-fig--night` 0 → 1，同时滑下去 |
| 切换后 | 只"变"（淡入淡出） | 只"沉"（滑 169px），**不跳版** |

两张图**必须都进 DOM 并预载**（暗色那组只是 `opacity: 0`，不是 `display: none`）——
否则切主题的瞬间会现下载一张图，闪一下。
**实测**：`opacity: 0` + `loading="lazy"` **会**加载（1 次请求）；`display: none` + `loading="lazy"` **不**加载（0 次请求）。
所以窄屏用 `display: none`（§2.8）既省流量，桌面用 `opacity: 0` 又保证切换不闪。

### 2.8 窄屏：≤720px 不画她（保留现状，理由与数字）

- **保留"窄屏不画她"**。理由：390 下卡的可见内容列只有 **290px**，而资料是"标签左、值右"、值贴右缘
  （实测 `.oshi-above` 右缘 = 320.2）——她那一列要 260px，**放进 290px 里必然压到数值**。
  她在手机上出场只有两种办法：把她缩到 100px 宽的条（脸读不出来，等于没有），
  或者把她改成"顶部横条"（那是另一个版式，不是把桌面版缩小）。**这一轮不做，留在 §8 待定。**
- **断点从 700 调到 720**：她的左侧轮廓 = 卡宽 − 168（实测推导）。721 视口下卡宽 681、
  文字最深墨迹 ~466 → **余量 47px**，成立；再窄余量就掉到 20px 以下。
- 窄屏**不会下载她的图**：`display: none` + `loading="lazy"` 实测 0 次请求。

### 2.9 暗色光柱要不要挪到她身上（建议做，值已算好）

现状 `.oshi-card::after` 的光柱在**左半边**（`polygon(26% 0, 58% 0, 44% 100%, 6% 100%)`，x 到 441），
而她那一列在 x 591–783 —— **光柱现在完全照不到她**。暗色的叙事是"光从水面漏下来打在她身上"，
建议把光柱移到她这一侧：

```css
.oshi-card::after {
  clip-path: polygon(70% 0, 94% 0, 100% 100%, 78% 100%);
  background: linear-gradient(
    180deg,
    oklch(0.88 0.06 var(--hue-accent) / 0.28) 0%,
    oklch(0.88 0.06 var(--hue-accent) / 0.18) 60%,
    transparent 96%
  );
}
```

- 光柱在 y=310（她的头顶）处横跨 x 565–737 → **正好罩住她的头**；渐变拉到 96% 才消失，
  所以她的脸（y 310–451）落在 alpha 0.19–0.10 的区间里，读得出"光打在她脸上"。
- 顺带的好处：左半边（文字区）不再被照亮 → 暗色文字对比度只会更好，不会变差。
- **不改也不会坏**（她自带的上方受光成立），只是光柱和人不发生关系。这是全卡**唯一一处发光**，位置换一下而已。

## 4. 去背与交付

### 4.1 绿键控（Pillow，一次性、可复跑）

1. 按 `#00FF00` 的距离建 alpha：`alpha = clamp((dist(green) - t0) / (t1 - t0))`，`t0 ≈ 60`、`t1 ≈ 150`，边缘 1px 羽化。
2. **去绿溢（必须做）**：对 `0 < alpha < 1` 的边缘像素做 unpremultiply 去绿（把 G 通道按邻近不透明像素的色相拉回），
   否则轮廓外会留一圈绿边。
3. **把完全透明像素的 RGB 填成邻近边缘色（必须做）**：`alpha == 0` 的像素若还是绿色，
   水下那层的 `blur()` + `brightness()` 会把它们糊出来 —— **轮廓外会出现一圈灰绿光晕**。
   做法：把 RGB 向透明区膨胀 2px（取最近的不透明像素色）。
4. 裁掉右侧**永远不会被看见的 116px 出血**（2:3 源图 1024 宽 → 保留左侧 708px），
   再缩到 **520×1128**，输出透明 WebP。
5. 不要用需要下载权重的抠图模型（确定性、可复跑是这里的硬要求）。

### 4.2 体积阶梯（红线：单张 ≤55KB）

| 档 | 参数 | 说明 |
|---|---|---|
| 1 | 520×1128 @ q80 | 目标档（已裁掉不可见出血，比 768×1152 省约 40%） |
| 2 | 520×1128 @ q72 | 平涂画面掉一档质量肉眼几乎看不出 |
| 3 | 440×954 @ q78 | = 显示尺寸的 1.7 倍，软边平涂在这个倍率下仍够 |
| 4 | 判据 | 以 `dist/_astro/*.webp` 的实际字节为准（源码体积 ≠ 交付体积） |

### 4.3 路径与加载

- 两张源图进 `blog/src/assets/oshi/`（透明 PNG 或 WebP 源），用 `astro:assets` 的 `Image` 出 WebP，
  拿内容哈希 → `/_astro/*` 的 immutable 长缓存。**不要往 `public/` 丢裸文件**（那是 7 天陈旧区）。
- `loading="lazy"` + `decoding="async"` + 显式 `width`/`height`（防 CLS）。**不在首屏**（这张卡是 `/about/` 第 4 个区块）。
- 尺寸固定（显示 260×564），**不需要多档 `srcset`**，一档 520×1128 即可。

## 5. 判断：要不要另外生成水族箱背景图

### 5.1 结论：**否掉。只出人物图（亮/暗两张），背景一张都不要。**

用户的想法是"分别生成水族箱背景图和人物图贴在现有卡片上"。**人物那半对，背景那半错。**

### 5.2 四条理由（都带实测）

1. **水槽已经是一套"活系统"，背景图会把它冻住。**
   现在的水是：4 个局部变量（水色）+ 两层无缝循环的 SVG 正弦浪 + 三层错拍波光 + 4 颗气泡 + 7 件造景 +
   倒影晃动，而且**亮暗是两套叙事**（亮 = 空气 + 水；暗 = 整张卡是水 + 一道光柱）。
   一张栅格背景图**不跟主题换色**（要换就得两张），**不会动**，而且会与 CSS 的浪/波光/气泡**同时"在水里动"**——两套水。
2. **它会被水色渐变盖掉（实测同 §2.3）。** `.oshi-below` 的水色渐变 alpha .96，
   任何画在它下面的东西只漏出约 4% —— 我把一块纯红放进那一层，量到的像素是 `(184,228,235)`，**纯水色**。
   想让背景图可见就得把水色 alpha 降下来，那会同时毁掉**刚调好的水色**与**刚过 AA 的文字对比度**（k 标签 5.82、主题句 12.08）。
3. **它会带来"第二处发光"。** 画出来的水族箱必然自带高光、光斑、气泡、水纹 —— 那是上一轮总结的
   "AI 味最重的来源"，而这张卡现在的纪律是**全卡只有一处发光**（暗色的光柱）。
4. **体积与维护**：2 张背景图（亮/暗）≈ +110KB，而 CSS 的水**零体积**、跟令牌走、改一个变量就能整体调色。
   已有方案 §8.2 也把"整卡背景画"列为"只有确实想要'整卡是一张画'的观感时才走"。

### 5.3 那"她"为什么值得出图？

因为**她是这张卡里唯一 CSS 画不出来的东西**：水槽是"系统"（有变量、有主题、有时间），
她是"物"（一张有脸、有姿势、有表情的画）。**给系统配一张画 = 把系统降级成图片；给系统放进一个人 = 让它有了主角。**

### 5.4 如果将来还是觉得右半太空（更便宜的三个做法，按优先级）

1. **CSS 再补一件造景**（零体积、跟主题换色）：右下的砂面上加一块半埋的卵石，**在她身后**（她在 z-index:1，天然在前）。
   注意右半现在故意留白给她，所以只加一件、且必须压得很低（在砂带里）。
2. **`A+D` 方案 §8.1 那条 5:1 透明装饰带**（可选，1 张 ≤60KB，剪影感、无光效，`opacity` 亮 .5 / 暗 .35）。
   它不承载信息，所以不碰文字对比度 —— 这是**唯一**值得考虑的"背景类"素材。
3. 其余（整卡背景画、2:1 横幅内景、粒子/水纹贴图）**一律不做**。

## 6. 验收清单

**几何（硬判据，可脚本化）**

1. 水线 = **282**（量 `.oshi-below` 的顶边相对 `.oshi-card`），且 721–1440 区间恒定。
2. 她的画布 top = 0、高 = **2 × 水线**（564）⇒ **下巴的像素 y == 水线的像素 y**（这条是"一个变量驱动三件事"的判据）。
3. **卡高 ≤ 2 × 水线**（今天 558.6 ≤ 564.2）—— 破了就见 §2.5 的补救。
4. **她压不到文字**：用 Pillow 读交付的透明 WebP，取 `alpha > 8` 的**最左列**，换算成卡内 x，断言 **> 480**
   （文字最深墨迹实测 477.2）。这一条把"不许压字"变成可执行的判据，不靠肉眼。
5. 右缘出血成立：她的轮廓在卡右缘处**确实被切断**（截图看右肩/右臂/马尾被切）。
6. 暗色下沉：暗色下她的**头顶像素 y > 水线 y**（实测应约 310 > 282）。
7. 切主题**不跳版**：亮暗两张截图中，文字与浪的位置**逐像素一致**，只有她变了（做一次像素 diff 目视）。

**流程**

8. 四门禁：`npm run build` / `npm run check`（0 errors）/ `npm run lint` / `npm test`。
9. 截图：1440 / 1024 / 768 × 亮 / 暗（六张，她出场的三个宽度），加 390 × 亮 / 暗两张看"她不在场时卡是否仍成立"。
   **滚动必须 `behavior:'instant'` 并等 `.reveal` 拿到 `is-visible`**，否则截到 `opacity: 0` 的空卡（教训 30）。
10. 体积：`dist/_astro/` 里每张 ≤55KB，合计 ≤110KB。
11. 窄屏不下载：390 视口下**对她的两个 URL 请求数为 0**（实测判据：`display:none` + `loading="lazy"` = 0 次）。

## 7. 亮暗 / 窄屏 / 体积 / 可访问性怎么过

**亮色**

- 她只有**水线以上**是清晰的（原图），**以下**是同一张图加 `saturate(.72) blur(1.5px)` + `opacity .94`
  → "头在水面上、身体在水里"由滤镜落差直接读出来，不需要模型理解"半身在水里"（那是模型最难画准的事）。
- 水面线由 `.oshi-figline` 在她身上补连续（§2.6）。
- 水色对比度不受影响：她永远在文字右侧（§1.5），且她不改任何文字颜色。

**暗色**

- 换图（编辑版）+ 下移 169px + 一层 `saturate(.72) blur(1.2px)`；不裁、无接缝。
- 她**必须是全卡最亮的东西**（光柱罩住她，§2.9）。检查：暗色截图里最亮的区域在她的脸，不是背景。
- 水面光（波光/浪）已压到 0.09–0.13 / 0.26–0.3，她进来后**不要**因为"看不清她"而把水光提亮 ——
  提亮就破了"全卡只有一处发光"。

**窄屏（≤720px）**

- 她 `display: none`；卡仍然完整成立（水的分层、倒影、签名句开关都在）。
- 卡高不增加（她的 DOM 是绝对定位、零尺寸锚点，不参与排版）——实测 390 仍是 794.5。
- 无横向滚动：她的出血方向是右，卡的 `overflow: hidden` 吃掉。

**体积**

- 2 个文件、每张 ≤55KB、合计 ≤110KB；`loading="lazy"` + `decoding="async"` + 显式宽高；不在首屏。
- 窄屏 0 请求（§2.8）。桌面两个文件都会加载（暗色那组 `opacity: 0` 也加载）——这是**为了切换不闪**，是故意的。

**可访问性**

- 她的 DOM 全部 `aria-hidden="true"`、`alt=""`：**装饰**，不加任何语义，读屏顺序与 DOM 顺序都不变。
- 卡内的信息仍全部是文本（六项资料 + 两件心事 + 主题句 + `sr-only` 的签名句），搜索"162cm""田辺留依"照样命中。
- 签名句"只在暗色浮现"的机制不动（§3.4 of A+D 方案）。
- **她身上没有任何承载信息的文字**，所以不存在"图代替文字"的对比度问题。
- `prefers-reduced-motion: reduce`：交叉淡入与下沉过渡全停（`transition: none`），切主题直接换状态。
- 键盘/读屏路径不变：她 `pointer-events: none`，不可聚焦。
