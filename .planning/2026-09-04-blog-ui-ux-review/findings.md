# 博客 UI/UX 评测发现

用于记录源码与浏览器检查得到的事实、证据和局限。

## 定位与现状
- 产品定位明确：真冬主题的个人二次元博客 / 独立游戏作品集，不是通用内容站。
- 设计系统已有较强一致性：单一 OKLCH 色相令牌、亮暗主题、霞鹜文楷、自托管素材、玻璃卡片、大圆角、统一阴影。
- 首页重点是氛围和人格表达，文章页重点是阅读；两类页面目前共用雪、Live2D、音乐 Dock、自定义光标等全局装饰。
- 2026-08-29 的功能质量审阅问题已在同日修复，本轮不重复把已修问题算作现状问题。

## 源码初步发现
- 正向：正文基准 18px/1.85，文章正文 1.03rem/1.9，容器 760px，长文可读性基础好。
- 正向：支持 prefers-reduced-motion；图片有尺寸/比例控制；桌面文章目录 sticky，小屏折叠。
- 风险：Header 的 GitHub/主题按钮为 38x38，小于常用 44x44 触控目标；音乐歌词按钮为 30x30、播放为 40x40。
- 风险：Live2D 在手机仍占 190x260 固定区域，音乐 Dock 同时固定右下，可能遮挡正文/页脚或造成视觉争夺。
- 风险：Live2D 模型和粒子持续 requestAnimationFrame，源码未见 prefers-reduced-motion 或 document.hidden 暂停逻辑；全局 CSS 只能把 CSS 动画压短，不能停止 JS RAF。
- 风险：文章 heroImage 使用 alt=""，若图片承载文章信息则会丢失语义；需要结合实际文章内容判断。
- 风险：多个交互主要定义 hover，源码未见统一 :focus-visible 样式或 skip link，键盘可见焦点可能依赖浏览器默认且不统一。
- 风格基线：通用设计系统推荐 content-first，但不能机械替换现有二次元视觉；本轮应保留品牌资产，优先处理阅读干扰、层级竞争和触控可达性。

## 浏览器实测
- 线上首页、博客列表、文章页均返回 200；本轮未发现 console error。
- 320x568 首页 document scrollWidth=340，相对视口横向溢出 20px；375/768/1440 抽测无横向溢出。
- 首页传输约 6.25MB，博客列表约 2.34MB，文章页约 2.06MB。首页最大项为 Live2D texture 2.12MB + moc3 1.19MB。
- 375px 首页 Live2D 固定 190x260；320x568 仍为 190x260，分别约占视口面积 16% 和 27%。
- reduced-motion 下 Intro 被移除，但 Live2D 完整资源仍加载、组件仍显示，粒子/注视 RAF 源码未见降级。
- 375px 长文章正文起点约 y=764，移动目录按钮约 y=5197；原因是单列后 DOM 仍正文在前、aside 在后。
- Header 头像/主题按钮 38x38；MusicDock 歌词 30x30、播放 40x40；手机 Live2D 切换按钮约 31x12/32x12。
- 全站未定义统一 :focus-visible；Tab 可达，但依赖浏览器默认 1px auto outline。未见 skip link。
- “回到顶部”与 MusicDock 滚动后没有重叠，不能列为问题。
- MusicDock 父级关闭时的 320x129 包围盒包含 visibility:hidden 面板，不等于全部可见遮挡；报告仅把常驻按钮和打开后面板分开讨论。

## 结论
- 不建议推倒重做或改成通用极简风；优化重点是按设备/页面降低装饰密度。
- 优先级：320px 溢出、Live2D 移动/加载成本、移动目录位置、触控目标、键盘焦点。
