# 出包魔法师故事成就与局后复盘设计 v2

> 日期：2026-09-06
> 状态：已确认，待制定实施计划
> 范围：故事成就、法师档案、本局故事、最近战报，以及与结算和复玩直接相关的关键 UX 修复
> 取代关系：本设计不删除 `2026-08-26-abraca-achievements-design.md`，但新版成就与迁移规则以本文为准

## 1. 背景与目标

现有成就主体是累计施法、击杀和夺冠次数。这些数字能记录投入，但很少改变玩家下一局的选择，也没有记录《出包魔法师》真正有趣的时刻：读牌、冒险连放、位置攻击、残血反杀、秘密牌生存和比分翻盘。

现状还有正确性问题：

- 游戏 Worker 已计算部分成就字段，但 Auth 清洗上报时丢弃，生产链路无法解锁对应成就。
- 部分统计字段只初始化、从未更新。
- “社死现场”要求单次行动失败三次，但规则在第一次失败后禁止继续施法，条件不可能成立。
- “奶龙大王”奖励累计巨龙失败和自爆，会诱导故意送分。
- 巨龙击杀没有进入通用击杀统计，导致首次击杀、累计击杀和零击杀冠军口径错误。
- 回合和比赛结算只展示结果，没有解释结束原因、得分来源和关键故事。

本次升级目标：

1. 让奖励条件与真实规则、服务端事实和生产数据链一致。
2. 用少量传奇成就记录高价值时刻，不再把累计数字包装成成就。
3. 每场比赛都能产生简短、可信的局后故事。
4. 玩家能在个人资料中回看最近比赛，而不是只看到静态奖章。
5. 修复直接阻碍理解和复玩的结算交互问题。

本次不做排行榜、赛季通行证、数值奖励、观战、准备系统、房主迁移、重赛投票和无限战报。

## 2. 领域术语

- **比赛 Match**：房主开始比赛后，到有人达到目标分并进入 `game_over`。
- **轮 Round**：发牌后开始，以击杀、清空手牌或自爆结束。
- **行动 Turn**：轮到一名玩家后，连续宣告若干次，最后主动结束回合。
- **事实 Fact**：服务端确认发生过的客观事件，例如“1 血击杀 3 血对手”。
- **故事 Story**：从事实中选出的局后展示内容，可以重复出现。
- **传奇成就 Achievement**：满足条件后只解锁一次。
- **法师档案 Career**：累计统计，不承担成就职责。
- **旧版纪念 Legacy**：玩家已解锁、但新版停止继续触发的旧成就。

## 3. 产品结构

### 3.1 传奇成就

传奇成就只记录第一次发生的稀有或有操作含量的时刻。首版 10 个，不奖励累计失败、自爆、拖延、聊天数量或故意送分。

| 成就 | 触发条件 | 当前数据状态 |
|---|---|---|
| 魔法阶梯 | 同一次行动连续成功施放至少 3 种不同魔法 | Worker 已有 `turnSpellSets`，Auth 当前丢弃 |
| 一气呵成 | 同一次行动连续成功至少 4 次，并以清空手牌结束该轮 | NEW DATA NEEDED：行动成功数与结束原因关联 |
| 八面玲珑 | 一场完整比赛成功使用全部 8 种魔法 | 现有 `spellsCast` 可判断 |
| 一线生机 | 只剩 1 点生命时赢下一轮 | 现有 `roundWonAtHp1` 可判断 |
| 以弱胜强 | 自己 1 血时，击杀受击前至少 3 血的玩家 | Worker 已有部分字段，需要补完整事实并通过 Auth |
| 夹击收网 | 一次非巨龙法术同时击杀两名玩家 | Worker 已有 `singleCastMultiKillNonDragon`，Auth 当前丢弃 |
| 龙息清场 | 一次古代巨龙成功击杀至少 3 名玩家 | 现有 `dragonOneCastKills` 可判断 |
| 拒绝结局 | 曾在自己不超过 3 分、对手至少 7 分时落后，最终夺冠 | Worker 已有 `comebackFromBehind`，Auth 当前丢弃 |
| 秘密投资人 | 任意玩家持有至少 3 张秘密牌并活到轮末 | NEW DATA NEEDED：记录所有幸存者，不只轮胜者 |
| 殊途同归 | 同一场至少一次靠击杀赢轮、一次靠清空手牌赢轮 | NEW DATA NEEDED：`roundWinsByReason` |

候选替补：

- **白手起家**：整场未成功使用猫头鹰，并以零秘密牌赢下一轮。
- **五系冠军**：最终夺冠，且本场成功使用至少 5 种魔法。
- **满桌开学**：完成一场五人比赛。

替补不与首版 10 个同时上线。上线后根据真实达成率替换条件重叠、过易或过难的成就。

### 3.2 法师档案

以下内容从成就系统迁出，作为职业生涯统计展示：

- 完成比赛数、冠军数、轮胜数。
- 成功施法总数和八系魔法成功次数。
- 总击杀、巨龙击杀、死亡和自爆。
- 最常用魔法、使用过的魔法种类。
- 最长连续成功施法数。
- 不同轮胜方式的次数。

击杀统一包含普通法术和巨龙击杀；`dragonKills` 作为子统计保留。累计统计只描述行为，不评判玩家强弱。

### 3.3 本局故事

本局故事可以重复出现，每场最多展示 3 条。故事只陈述服务端能够证明的事实。

优先级：

| 级别 | 内容 | 示例 |
|---|---|---|
| S | 改变比赛结局 | 从 2:7 落后完成翻盘；巨龙一次击倒三人 |
| A | 极限操作 | 1 血反杀；连续成功四次并清空手牌 |
| B | 获胜路线 | 靠秘密牌获得 3 分；分别靠击杀和清空手牌赢轮 |
| C | 风格记录 | 本场使用 6 种魔法；连续多次成功后主动收手 |

选择规则：

1. 按 S、A、B、C 排序。
2. 同类故事保留信息最完整的一条。
3. 最多 3 条，不用低价值内容填满空位。
4. 新成就可以引用同一事实，但结算中故事和成就分区展示。
5. 文案不使用“神级”“史诗”等主观评价，不把骰子结果包装成玩家技术。

故事结构：

```js
{
  key: 'low_hp_kill',
  playerId: 'p...',
  tier: 'A',
  data: {
    round: 4,
    spellId: 7,
    actorHp: 1,
    targetHpBefore: 3,
    targetPlayerId: 'p...'
  }
}
```

前端根据固定 `key` 和结构化 `data` 渲染中文，不接收客户端提交的任意文案。

### 3.4 最近战报

每名持久账号保存最近 10 场个人战报：

- 日期、参与人数、轮数、名次和最终比分。
- 当场最终排名和昵称快照。
- 当前玩家最多 3 条故事。
- 当场新解锁的传奇成就。

不保存聊天、表情、IP、设备信息、其他玩家完整手牌或逐步操作。第 11 场写入后删除最旧记录。

游客可以在当前结算查看故事，但不保存到个人资料。当前游客身份依赖本地存储，清理浏览器后无法可靠找回，不承诺持久战报。

## 4. 旧成就迁移

| 旧成就类型 | 新版处理 |
|---|---|
| 已解锁的计数成就 | 保留为“旧版纪念”，累计数字进入法师档案 |
| 未解锁的计数成就 | 不再显示为成就，进度进入法师档案 |
| 条件正确且有故事性的成就 | 合并进新版，例如“一线生机”“龙来” |
| 描述与实现不一致 | 按真实规则重命名并重写条件 |
| 不可能完成 | 停用，例如“社死现场” |
| 鼓励坏玩法 | 停用，例如累计巨龙失败和自爆的“奶龙大王” |
| 已解锁但已停用 | 仍可查看，标记“旧版纪念” |
| 隐藏彩蛋 | 未解锁显示“？？？”，解锁后玩家本人可正常查看 |

成就定义增加状态：

- `active`：新版正常触发和展示。
- `legacy`：停止触发，仅向已解锁玩家展示。
- `hidden`：未解锁隐藏内容，解锁后正常展示。

难度星级改名为“难度”。真实稀有度必须基于实际解锁率，首版没有这项数据，不能把人工分级称为稀有度。

旧比赛没有保存完整事实，首版不回算无法可靠证明的新成就。

## 5. 结算交互

### 5.1 回合结束

回合结束页依次展示：

1. 获胜者、决定性魔法和结束原因。
2. 每名玩家本轮得分拆分：轮胜、幸存、秘密牌。
3. 公开所有手牌和秘密牌。
4. 当前玩家“你手里原来有”的牌面摘要。
5. 当前比分、目标 8 分和每人距离胜利的分数。
6. 房主的“开启下一轮”操作。

结束原因文案必须区分：

- 击杀结束。
- 清空手牌结束。
- 施法失败自爆结束。

### 5.2 比赛结束

比赛结算页依次展示：

1. 冠军与最终排名。
2. 每人比分、轮胜次数和关键统计。
3. 最多 3 张本局故事卡。
4. 最多突出展示 2 个新解锁成就，其余折叠。
5. “再来一局”主按钮。
6. 查看完整统计和返回大厅的次要入口。

关闭结算详情后，“再来一局”入口仍然有效。首版仍由房主正式发起重赛，不加入重赛投票。

### 5.3 同步修复的关键 UX

- 修正规则帮助中“猜错后自动结束回合”的错误描述。
- 猫头鹰没有拿到秘密牌时，不提示“获得秘密牌”。
- 新比赛开始时清空 `newAchievements`，避免重复展示旧成就。
- 常驻显示“先到 8 分”和距离胜利分数。
- 魔法效果不能只放在鼠标 `title`，手机也必须能查看。
- Auth 上报或战报保存失败不阻止结算和重赛，只提示“战报暂未保存”。

本版不处理房间加入失败、房主迁移、准备状态和移动端施法区整体重排。它们已确认有价值，但属于独立的房间生命周期与游戏桌面 UX 项目。

## 6. 模块职责

### 6.1 Abracadawhat Durable Object

- 继续作为牌局事实来源。
- 记录行动序列、轮胜原因、分数来源、关键血量、秘密牌和比分快照。
- 生成结构化事实。
- 在 `game_over` 广播中立即附带故事，确保 Auth 故障不影响结算。
- 异步上报 Auth，不等待 Auth 才允许玩家重赛。

### 6.2 纯规则与故事模块

- 输入服务端统计，输出事实和最多 3 条结构化故事。
- 负责故事优先级、去重和数据完整性。
- 不依赖 Vue、DOM、WebSocket 或数据库。
- 同一输入必须得到同一输出，便于单元测试。

### 6.3 Auth Worker

- 校验新版战绩协议并保留允许字段。
- 根据服务端事实解锁传奇成就。
- 更新法师档案。
- 为持久账号保存最近战报。
- 兼容旧版上报，迁移期间不阻断其他游戏。

### 6.4 个人资料页

- 展示传奇成就、法师档案、旧版纪念和最近战报。
- 不重新计算成就或故事。
- 不把未解锁的隐藏成就内容泄露给普通玩家。

## 7. 新版战绩协议

以下是拟新增协议，不是现有接口：

```js
{
  schemaVersion: 2,
  game: 'abracadawhat',
  roomId: 'ABC123',
  rounds: 5,
  standings: [
    {
      playerId: 'p...',
      nickname: '玩家',
      rank: 1,
      score: 9,
      scoreBySource: {
        roundWinPoints: 6,
        survivalPoints: 1,
        secretPoints: 2
      },
      spellCounts: { '1': 1, '7': 3, '8': 2 },
      kills: 2,
      dragonKills: 1,
      deaths: 1,
      roundWinsByReason: { kill: 1, all_spells: 1 },
      maxTurnCastCount: 4,
      maxTurnDistinctSpells: 3
    }
  ],
  facts: [],
  stories: []
}
```

协议约束：

- `facts` 和 `stories` 使用固定 key 白名单。
- 限制数组数量、字符串长度和数值范围。
- 身份以 `playerId` 为准，昵称只是当场快照。
- 不上报聊天、表情、IP 或设备信息。
- 通用 `kills` 包含所有击杀，`dragonKills` 是其中的子集。
- `schemaVersion: 1` 暂时继续支持。

## 8. Auth 存储

新增最近战报表：

```text
player_match_reports
- id
- match_id
- player_id
- game
- rank
- score
- rounds
- player_count
- standings_json
- stories_json
- unlocked_keys_json
- finished_at
```

约束：

- `match_id + player_id` 唯一，重试上报不重复写入。
- 每名玩家每个游戏最多保留最近 10 条。
- 写入后删除第 11 条及更旧记录。
- 游客不保存最近战报。
- 职业生涯累计继续使用完整历史，不从最近 10 场倒算。

Auth 返回结果至少包含：

```js
{
  ok: true,
  matchId,
  savedReports: ['p...'],
  newAchievements: []
}
```

## 9. 结算时序与失败处理

1. Durable Object 完成比赛并生成最终排名、事实和故事。
2. Durable Object 立即广播 `game_over`，前端展示完整结算。
3. Durable Object 使用 `waitUntil` 异步上报 Auth。
4. Auth 校验、写入比赛、更新档案、保存最近战报并解锁成就。
5. Auth 返回新成就，游戏将其合并进当前结算。
6. Auth 失败时记录错误并显示“战报暂未保存”，不阻止重赛。

首版不引入队列。必须保留失败日志，并保证 `match_id + player_id` 幂等，为后续重试留接口。

## 10. 测试与验收

### 10.1 单元测试

- 分数来源、轮胜原因、行动连放、击杀前后血量和秘密牌。
- 故事优先级、最多 3 条、同类去重和数据完整性。
- 10 个传奇成就的成功与反例。
- 巨龙击杀进入通用击杀统计。
- 不可能和坏激励的旧成就停止触发。

### 10.2 集成测试

- 游戏报告经过 Auth 清洗后字段不丢失。
- 新旧 `schemaVersion` 都能被正确处理。
- 重复上报不重复保存战报或解锁成就。
- 每名玩家只保留最近 10 场。
- 游客不持久保存最近战报。
- Auth 失败不阻止游戏结算和重赛。

### 10.3 UI 与生产验收

- 回合结束显示原因、赢家和得分拆分。
- 比赛结束显示最多 3 条故事和新解锁成就。
- 关闭结算后仍能重赛。
- 下一场不重复显示旧成就。
- 手机可以查看魔法效果。
- 完成一场可控生产测试局，核对游戏结算、个人资料最近战报和成就只解锁一次。

## 11. 实施阶段

### A. 正确性修复

- 修复 Auth 字段清洗和完整链路测试。
- 统一击杀口径。
- 停用不可达或鼓励坏玩法的成就。
- 修正规则文案、猫头鹰反馈、旧成就残留和重赛入口。

### B. 故事引擎

- 补齐服务端统计和事实。
- 实现故事优先级、去重和最多 3 条。
- 升级回合与比赛结算页。

### C. 传奇成就与法师档案

- 上线首版 10 个传奇成就。
- 迁移旧成就展示。
- 把累计数据改为法师档案。

### D. 最近战报

- 增加 Auth 存储与查询接口。
- 个人资料页展示最近 10 场。
- 完成幂等、保留数量和隐私测试。

四个阶段分别验证，不把准备系统、房主迁移、重赛投票或桌面整体重排混入本计划。

## 12. 风险与约束

- 先修数据可信度，再增加成就。纯判定函数测试不能替代完整上报链路测试。
- 不奖励累计失败、自爆、送分、拖延或聊天量。
- 社交成就不绑定轮流获胜，避免固定房互刷。
- 周期挑战如果以后加入，只给称号、印章或展示，不改变牌局数值。
- 旧数据无法证明的故事和成就不补发。
- 不把人工难度称为真实稀有度。
- 不让故事系统替玩家计算最优牌，保留“看得到别人、看不到自己”的推理空间。
