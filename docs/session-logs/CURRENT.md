**水位线在哪是量出来的，不是估的**（用户反馈"水位动效可以提高一点，接近图里的水位"）。
逐列找"空气→水的过渡"（纵向梯度最大行）：**白天 30.3%、夜里 33.0%**；高光线 32.9%/32.8%。
正弦在 viewBox 里居中（y=20/40），所以 `top = 水位 − height/2`：现在是 `top: 27.6% / height: 5.6%`
→ 正弦中心 **30.4%**，压在白天那条水位线上。
（第一版放在 30.2%，正弦中心 33.0% —— 那是压在**高光线**上，比"水位"低了约 3%，肉眼看就是"线沉在水面下"。）
验证办法：`playwright-oshi-preview-check.py` 会顺手出一张带百分比标尺的水线裁片 `ruler-{theme}.png`，
每 2% 一条刻度，直接对着看图里的水位和波形有没有重合。

**"滚动 → 水面波动"的三个关键决定**（这段是本轮最值钱的部分）：

1. **驱动量是卡片自己的视口位置变化，不是 `window.scrollY`**（用户点破：
   "拖拽 滚动都是一样的吧 都是这个卡片在用户的视角位置变了"）。对水来说，滚轮 / 拖滚动条 /
   键盘 / 锚点 / 惯性 / 将来某个容器内滚动都只是同一件事。只认 `getBoundingClientRect().top`
   的逐帧差，就不必枚举来源（枚举必然漏）。
2. **移动不直接映射成波形，而是给一个冲量，让阻尼弹簧自己荡回去** —— 直接映射读起来像滑块，
   一停就僵在最大位。弹簧 `K=0.010`（周期约 1.05s，水的节奏；0.022 像果冻）、
   `DAMPING=0.978`（约 3s 荡平）。
3. **按时间积分，不按帧**（`dt` 以 60fps 为 1 个单位）：不这么做 120Hz 屏上衰减快一倍。
   冲量那边不必换算——一次滚动 D 像素的总冲量恒为 D×增益。

实测响应：轻滚 120px → 峰值 0.35；正常滚 420px → 0.84；快滚 480px → 1.00（短暂顶格）；
**reduced-motion → 全程 0.000**。弹簧有 6 次正负翻转（真的在回弹，不是滑块）。

## 环境与权限

- **blog 验证不必起 wrangler**：纯静态站，用 `python -m http.server 8777` 指向 `blog/dist`
  + Playwright，比 `npm run dev` / `astro preview` 快得多，也绕开了下面那个 preview 残留的坑。
  联机游戏页面仍必须 `npx wrangler dev`（`vite dev` / `vite preview` 没有 `/ws`、`/api` 代理）。
- blog 部署：`cd blog && npx wrangler deploy`（**家机** wrangler 已登录，实测通过）。
  `npm run build` 会触发 `postbuild` 预压 Live2D moc3；**绕过 build 直接 deploy 会部署上一次的 `dist/`**。
- **`astro preview` 是常驻守护进程**：`TaskStop` 杀外壳后它仍活着并占着 3000，用 `npx astro preview stop` 停。
- **两个 Python 别搞混**（本轮新增，吃过一次亏）：
  - 图像分析（PIL/numpy/scipy）用 `C:\Tool\ImageGen\ComfyUI\.venv\Scripts\python.exe` —— **它没有 Playwright**；
  - Playwright 用系统 `python`（3.14）—— **它没有 PIL/numpy**。
  所以"算图"和"开浏览器"是两条命令，不能写在同一个脚本里。
- **Playwright 验证四条纪律**：轮询到条件成立（别 sleep）；`data-testid` 定位（别按显示名）；
  不用 `networkidle` 判成败；**滚动触发型页面必须 `behavior: 'instant'` 滚动**（站点开了 smooth scroll，
  否则 `scrollTo` 全程是动画，`.reveal` 假不触发）。
- **验主题相关的行为必须摆对首帧**：`data-theme` 由 `BaseHead.astro` 的内联脚本在首帧前读
  `localStorage` 设好。测试要用 `context.add_init_script` 写 `localStorage.theme`；
  先 `load` 再改属性会得到假结果（本轮差点据此判定"懒图优化无效"）。
- 用 `urllib` / `curl` 手查线上资源**必须带浏览器 UA**（否则 Cloudflare 403）；
  Git Bash 的 curl 有 TLS 握手问题，直接用 Python urllib。
- **临时产物别留在仓库**：仓库根的 `_out/` 本轮已删除，脚本输出**统一改道**
  `docs/agent/scripts/out/`（那个目录才是被 gitignore 的）。仓库里不写盘符，脚本用自身位置定位。
- workerd 子进程不随父进程退出，残留按 PID 杀；别按命令行批量杀（会匹配到自己）。
- 更多：根与 blog 各自的 `docs/lessons-learned.md`（本轮新增 37–41，其中 37 是"顺序反了"那条）。
