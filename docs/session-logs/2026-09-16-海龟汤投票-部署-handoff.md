## 这是什么

用户否掉了"跨游戏战绩与成就看板"这条建议（三个游戏的"厉害"不是同一种东西，硬塞进一张表
等于规定它们可以互相兑换），改成**海龟汤每局揭底后做一次投票**：把 🍎 送给这一局你觉得
发挥最好的玩家。目的是"让一起玩的人高兴高兴、看看谁猜得好"——**不是战绩、不计入历史、不做防刷分**。
观众不能送 🍎，改成送小红花（临时点赞）。

## 关键决策（git 查不到的部分）

- **🍎 是"我的名单"，不是"一票"。** 这是让「玩家点别人即换人」和「主持人有两份」共存的关键：
  目标已在名单里 → 再点即撤回；名单没满 → 加入；**满了 → 顶掉最早的**。
  于是玩家（名额 1）点别人自然换人，主持人（名额 2）天然保留最近两个，
  而且两份不可能落在同一个人头上。整个过程**不需要任何错误提示**，正好对上"顺手就点了"。
- **🍎 计数隐藏到投票结束**（`appleCounts` 在前端拿到的是 `null`）：投的过程中互相看得见会从众。
  只下发"我自己的名单"+ 一个不泄露方向的进度（已有几人送出）。
- **小红花反过来，一直可见。** 它只是点赞，**没人看得见就不叫点赞**。
  同一观众对同一玩家只有一朵，再点收回——天然限流，不需要额外规则。
- **全员送满自动收口**（计划里只写了房主按钮）。不加这条，房主一 AFK 面板就永远等不到结果。
  掉线的人仍算在 voters 里，所以不会误关；那种情况需要房主点按钮——有意为之，防短暂重连提前关掉。
- **AI 复盘提示一并关闭。** `handleAIHint` 会真的往 `AI_BASE_URL` 打请求，独立于主持模式，
  主持人/房主随时可触发；不关它"关掉 AI 入口"只关了一半。用户给的理由（token 成本）对它同样成立。
- **验证不再依赖昵称**：生产有 auth，游客身份会覆盖玩家在大厅输入的名字，
  于是"按昵称找按钮"的脚本本地过、生产找不到。改挂 `data-testid`（仓库里出包就是这么做的）。

## 顺带查实/修掉的

1. **`win.gif` 庆祝页现在走不到了。** 人类模式两条结束路径
   （主持人确认猜中 `soupRoom.js:507-524`、房主揭底 `handleReveal`）**都直接置 `revealed=true`**，
   所以 `phase==='ended' && !revealed` 这个组合不会出现。以前只有 AI 模式能走到它，
   Phase 1 关掉 AI 之后这段就成了死代码。**没改**（要改是行为变更：让确认猜中时先不揭底，
   多点一下看 GIF），留给用户决定。
2. **结束覆盖层的 `@click` 没有 `.self`**：揭底后点到卡片里任何位置（包括选中文字）
   都会直接"返回大厅"。已改成只有庆祝块承接点击、出口只认按钮。
3. **`HostConfigPanel` 的「本局人数（含主持人」缺右括号**，已补。
4. **`docs/agent/scripts/playwright-verify-deploy.py` 用 `networkidle` 判成败会产生假 FAIL**：
   同一脚本连跑两次，在不同站点各假失败一次（blog 与 soup），而同一时刻 curl 都是 200。
   改成 `domcontentloaded` 判成败、后续等待尽力而为。顺带把 `net::ERR_ABORTED`
   （浏览器主动取消的媒体预加载）从"失败请求"里分出来——那条噪音每次验收都要重判一遍。

## 踩坑记录

1. **声明了、hydrate 了，但忘了从 store 导出。** pinia 上取到 `undefined`，
   面板渲染到一半**整块消失**（只剩一个空覆盖层），而构建绿、单测绿、`pageerror` 也没有
   （Vue 把它记进 console.error 而非 pageerror）。回归测试因此改成
   「声明 / hydrate / 导出」三件**分别**断言。
2. **固定 `sleep` 在生产上必然出假故障。** 同一个投票脚本本地全绿、生产 3 条失败，
   查下来是"某一页还没收到广播"。等待要轮询到条件成立（`wait_text`），不能按秒数。
   这已经是同一类坑在本仓库的第三次记录。
3. **按显示名定位元素不可靠。** 生产有 auth，游客身份覆盖昵称 → 本地过生产挂。锚点要挂 `data-testid`。
4. **我自己的范围断言被一个属性撑爆。** `从 <button 起算 200 字符内出现「返回大厅」`
   在加了 `data-testid` 之后失配，而失败信息只说"找不到"。改成按 testid 定位到那一个 `<button>`。
5. **`networkidle` 不是可用的判据**（见上）。另外生产上 `page.screenshot()` 会卡在
   "waiting for fonts to load"，截图不能进判据链。
