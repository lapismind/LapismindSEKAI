# 首页「SEKAI 精选」与「SEKAI is running」重做 · 上线交接

> 日期：2026-09-20
> 执行机器：**家机**
> 性质：首页两个板块重做 + 生产部署
> 生产版本：blog `5ff59956`
> 本轮起于用户的一句提问：「首页『精选游戏』你觉得有存在的必要性吗？」

## 本轮目标

用户指出首页两块已经"早期项目占位符级别"：「精选游戏」和「现在在做」。其中「现在在做」不只是占位，
它写的状态是**错的**——文案说"正在开发：出包魔法师"，而那个游戏早已上线。

## 执行摘要

### 1. 「精选游戏」→「SEKAI 精选」（跨栏目）

实测出三个问题同时成立：

- **"精选"是假的**：`featured: true` 标在**全部三个**游戏上，`featured` 等于全集；
- **和 `/projects/` 是同一份数据的两次渲染**（同样的标题/副标题/描述/技术标签，链接也指向同一批详情页），
  省下的只是一个点击，代价是手机端这一块独占**整页 37%**（1563 / 4183px）；
- **执行方向反了**：首页是全站曝光最高的地方，三张卡却只有 1 张有图，另外两张退化成一个汉字占位
  （「出」「梭」），而唯一有图的那张用的还是**旧的大厅实机截图**——正是上一轮做封面时想取代掉的那类图。

改法：`featured` 收成两条——出包魔法师（游戏，详情页 `/projects/`）+ 法杖盾斧（Projects 板块，
详情页 `/works/`）；href 在数据层拼好（两个路由不同）；标题行右侧从单个"全部游戏 →"扩成两个入口。
手机端该块 1563 → **1081px**，整页 4183 → **3700px**。

### 2. 「现在在做」→「SEKAI is running」运行面板

改法：三段式布局——顶行（`status · 运行状态` + 右上角「最近更新 日期」）、
中间（呼吸式运行指示灯 + `SEKAI is running` + 副行）、底行（四格读数：游戏 / 已上线 / 曲库 / 文章）。
**所有数字与日期都在构建期算出来**（`projects.ts` / `music-player.json` / 博客集合），不会再过期。
手机端卡片 498 → **372px**；桌面 297px。

副行文案由用户定为一句捏他：**「现在，我将演示 SEKAI 运行的框架。」**（出自牛顿那句，把"世界"换成"SEKAI"）。
注意它承担的是**姿态**而不是状态陈述——"还在运营"这个意思现在由标题、指示灯、「最近更新」的日期共同表达。

## 关键决策

1. **盾斧 mod 的卡片图用裁切而不是合成**。`preview_staff.jpg` 是 640×1760 的竖长图，2:1 画幅直接裁只剩
   一条横切片；合成"产品板"（缩小居中 + 主色辉光）让物体细得像一根线；实机截图居中裁（`defend.png` /
   `axe.png`）虽然法阵清楚，但分辨率低、暖沙色调与站点冷色体系打架，画面里还有货车兽骨与按键提示。
   最后取**顶部杖首/表盘特写**（`preview_staff.jpg` 裁 y=25–345，640×320），既保住"时钟法阵"这个签名特征，
   又与站点冷色同族，而且它是 mod 自己的主视图、不是新造的东西。→
   `blog/src/assets/works/staff-card.jpg`（28KB，构建后 webp 13KB）。
2. **状态文案的规矩**：凡**事实**（有几个游戏、几首歌、几篇文章、最近更新何时）一律构建期从数据算；
   只有**意图**（下一步做什么）才允许手写，而意图只有用户能提供。这条是本轮最有复用价值的结论。

## 踩坑记录

- **`.section-title .more-link` 的 `margin-left:auto` 只适合单个链接**（在 `global.css`）。两条并排时
  各自抢空白会互相推开，必须用容器接管 `margin-left`、再收回子项的（本轮加的 `.more-links`）。
- **"精选"必须先确认它不是全集**。判据：看它和目的页是不是同一份数据的两次渲染——若是，这个板块
  就只是一次多余的点击成本，而首页的垂直空间是按屏付账的。
- **写死的状态文案必然过期**。`blog/docs/review-2026-08-29.md` 第 80 条早记过"写死状态文案"，
  本轮撞上的正是它烂掉的样子。
- **320 宽下页头有 43px 横向溢出**（既有问题，本轮未修）：把 `#featured` 整个 `display:none` 后
  `scrollWidth` 不变（仍 363），说明溢出源全在页头（导航 + 主题按钮）。
