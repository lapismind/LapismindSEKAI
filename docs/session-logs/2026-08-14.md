## 踩坑记录

### 坑1：Hibernation 模式下内存状态丢失
- 现象：玩家2能看到1，1看不到2；准备点不了；出牌全失败。本地快速连接测试却通过，线上必炸。
- 根因：用内存 Map（`this.socketToPlayer`）记录"连接<->玩家"。DO 进入 Hibernation 休眠后内存清空，唤醒后连接映射丢失，广播找不到 socket、操作消息查不到 playerId 被静默忽略。
- 修复：改用 Hibernation 官方机制——`socket.serializeAttachment({ playerId })` 把 playerId 挂到连接上（随连接持久化），遍历用 `this.ctx.getWebSockets()`。本地用"等待20秒强制休眠->唤醒后操作"测试验证。

### 坑2：最大牌 K 卡死全场
- 现象：有人打出全场最大 K 后，所有人都大不过，只能无限跳过，死局。
- 根因：规则"必须出 >= 上家"，无兜底机制。
- 修复：增加 passCount + roundLeader 追踪。全场其他人都跳过时 -> 桌面清空（topCard=null）-> 回到最后出牌者重新起头；起头时不允许跳过；超时自动跳过也走同一逻辑。

### 坑3（部署相关）：免费计划 DO 要求 SQLite 后端
- 现象：`wrangler deploy` 报错 code:10097，提示 free plan 必须用 `new_sqlite_classes` migration。
- 修复：wrangler.toml 里 migrations 从 `new_classes` 改为 `new_sqlite_classes`。

### 坑4（环境相关）：本机到 Cloudflare 网络不稳定
- 现象：REST/WebSocket 验证时好时坏（ETIMEDOUT / HTTP 000），wrangler tail 也连不上。
- 根因：本机出口到 Cloudflare 的连通性不稳（疑似网络环境），与代码无关。
- 影响：线上验证需在网络稳定时进行；部署本身成功。
