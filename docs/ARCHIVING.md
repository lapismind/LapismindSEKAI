# 代码项目归档规则

本仓库使用 Git 记录代码变化。会话归档用于帮助 Agent 理解项目进度，不做每日工作流水账。

## 存放位置

- 项目相关交接日志放在对应项目的 `docs/session-logs/`。
- 跨项目决策或仓库级交接日志放在根目录 `docs/session-logs/`。
- 没有 `docs/session-logs/` 时可以创建。
- `docs/博物馆/` 只保存已经成为历史、后续不再修改的长期材料，不放日常交接日志。

## 何时归档

以下情况需要归档：

- 完成一轮重要功能或集中修复。
- 完成生产部署，需要记录线上版本和验证证据。
- 工作需要跨会话或跨 Agent 继续。
- 关键设计决策无法仅从 Git diff 和提交信息中理解。

普通的小改动不单独归档，Git 提交已经足够。

## 记录内容

归档重点记录 Git 不擅长表达的信息：

- 本轮目标和当前完成度。
- 问题背景与根因。
- 关键决策及其原因。
- 测试、构建、浏览器验证等证据。
- 生产地址、部署版本和回滚入口。
- 已知风险、阻塞项和下一步建议。
- 下次接手需要加载的技能与关键文件。

不要重复粘贴完整 diff、逐条罗列所有文件改动，也不要记录可以直接从 Git 查到的流水信息。

## 日志维护

- 同一事项继续推进时，优先更新对应的里程碑日志。
- 出现新的独立目标时，再新建日志。
- 文件名使用 `YYYY-MM-DD-主题-handoff.md`。
- 日志中不写密钥、Cookie、Token 等敏感信息，只写所需服务和权限。
- 结论必须附验证依据；未验证的内容明确标为待确认。

## 推荐结构

```markdown
# [主题]交接

> 日期：YYYY-MM-DD
> 性质：功能 / 修复 / 部署 / 架构决策
> Git 提交：`commit`

## 本轮目标
## 执行摘要
## 关键决策
## 验证证据
## 生产状态
## 关键文件
## 踩坑记录
## 当前状态
## 推荐技能
## 环境与权限
## 阻塞项
## 下次可做之事
```
